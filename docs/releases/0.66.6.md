# Arugula 0.66.6

A deploy is approved with one passkey, on the page the push opens. Run grants and team owner changes take a passkey too, and the device-key rules behind them are gone from those paths. The agent block and the conversations list estimate what a session costs at API prices, a terminal running Claude Code shows its live context, and the swarm has a wall mode for a TV. Update every machine.

## Changed

- **A deploy approval is one passkey** (#1943, Arugula #385). Approving or denying a deploy is one passkey confirmation over the deploy, its operation, your account, the decision and when it expires. Your browser's device key no longer signs it, and it doesn't matter which device approved which (aru-126). The platform checks it against your published passkey log, and so does the deploy's box, against the log it was given by control when it started.
- **Approve where the push opens it** (#1951, Arugula #386). The deploy's page on the platform, and its card in your inbox, have **Approve with passkey** and **Deny with passkey**, with the checked plan beside them. The page asks first whether you can decide (owner, passkey, still pending) and says why not instead of offering a button that fails. Where a browser or password manager can't use control's passkeys on the platform page, or the window has no passkeys (the Linux app), **Approve on Control** takes you to control's page as before. An owner who asks for an approval gets the push too, and an agent's `read_deploy` can wait for the decision (`until: decided`).
- **Run grants are signed with a passkey** (#1953, Arugula #387). Allow runs, Renew and Revoke ask for a passkey. A hosted box checks the grant against the passkey log control gave it. Grants signed the old way keep working until they expire, and none are accepted after 2027-11-02.
- **Team owner changes take a passkey** (#1950, Arugula #388). Making someone an owner, removing an owner or demoting one asks for a passkey from an owner, and control keeps the proof with the roster. The roster is still signed by a device for your machines, and a CLI still can't change who the owners are (aru-056). A team's founding member must be the account creating it.
- **Estimated cost at API prices** (#1945, #398). The agent block's strip shows "≈ $X at API prices" for the session and its subagents, from their transcripts' token counts. Clicking it shows each part. The conversations list shows each conversation's estimate.
- **Claude Code's live context in a terminal** (#1962, #450). With the plugin's live session signals on (#1959, off by default: `/config`, "Live session signals"), `claude` in a terminal pane shows its context fill, compaction mark and cost in the pane's header, and an agent block uses the live figures over its transcript's.
- **Swarm wall mode** (#1952, #446). **Wall mode** beside Fit, or `w`, hides the chrome around the swarm and asks for fullscreen. Esc or **Exit wall mode** brings it back.
- **Needs you in one order** (#1957, #451). Every list of what wants you puts gates first, then other asks, then failures, then finished work.

## Fixed

- **A 1M session's fill** (#1960, #444). The agent block read Sonnet 5.5, Haiku 5.5 and Opus 5.5 sessions against a 200k window, so a 141k session showed 71% and dipped after compacting. It reads them against 1M.
- **Hosted prices** (#1949). The price table hosted calls are charged at, and the estimates show, matches Anthropic's list prices as of 2026-10-31.

## Note

- **Update control and every machine together.** A deploy's box from before this release refuses the new approvals (it cancels the deploy and tells the owners), and hosted boxes from before it refuse passkey-signed run grants and ignore their revokes.
- **Run grants:** don't Renew, Allow runs or Revoke on a project until its hosted workspaces run this release. A grant you already have keeps working until it expires.
- **Approvals already given** keep applying until they expire (7 days at most). A control page opened before the update asks you to reload before you approve.
- **Owner changes from the desktop app** wait until every machine on the team runs this release (they say which one hasn't). Owner changes from a browser don't wait.
- `just demo-fleet` (#1944) brings up a seeded demo fleet for screenshots and load, and the e2e suite runs axe on the main pages in light and dark, at desktop and phone widths (#1931).
