# Arugula 0.60.1

Deploys get their pages, CLI and agent tools (M252), and accounts whose
browsers an app window approved can add a passkey again, which approving a
deploy takes.

## Deploys

- **Environments, secrets and planning** (M252, #1378). Project settings
  list a project's environments, and owners make them there: a driver, its
  settings and the secret names it may hold. Owners set each secret from
  the page; a value is sent once and never shown again.
- **Deploy…** plans a deploy of a commit to an environment, shows the plan,
  and asks the owners to approve it. Approving stays on the phone or in a
  browser, with a passkey.
- **`arugula deploys envs|plan|request|show`** in the CLI. There's no
  approve command, and no secrets.
- **Agents plan and ask** with MCP's `plan_deploy` and `read_deploy`, under
  the machine's `deploys.plan` grant. They never approve.
- A plan names its environment by id or by name.

## Fixes

- Tapping a push about a deploy waiting for approval, or an inbox item, opens it, not control's page (#1383).
- **Adding a first passkey works again for every account** (#1386). Since
  0.59.0 a first passkey needed one of the account's browsers to sign for
  it, and browsers an app window approved before then didn't count, so
  some accounts couldn't add one at all. A first passkey now also takes a
  GitHub sign-in from the last ten minutes: the page sends you through
  GitHub when it needs one. A second passkey still takes one you have.
