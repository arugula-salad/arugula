# Arugula 0.39.3

Fixes from M50's live checks (#150, blocks through control) on the phone
and the Mac app, and a few from CI.

## Blocks

- **Open a port… offers what's listening** (#932): the prompt shows the
  ports that answer on the block's machine as buttons, the pane's own
  first, instead of an example number that looked real. Free text still
  works, and a daemon without the new list just gets the text box.
- **Why a block went relayed** (#926, #849): Chrome's Local Network Access
  keeps a block's worker off tailnet addresses, so it no longer tries the
  direct route there and goes straight to control's relay. Control's page
  now frames blocks with `allow="local-network"`, so a block's WebSockets
  (hot reload, the editor) can still go direct. The route pill's tooltip
  says why it's relayed.

## Also

- **Attaching doesn't wake a finished pane** (#925, #909): drawing a Claude
  Code pane for a new web client sent it a focus-out it never asked for,
  and the pane showed as working.
- **PTYs open one at a time** (#927, #916): macOS `openpty` isn't
  thread-safe, and two panes starting together could share a terminal.
- **`arugula hooks install` follows `CLAUDE_CONFIG_DIR`** (#928, #879)
  instead of always writing `~/.claude/settings.json`.
