# Arugula 0.70.36

Claude Code in VS Code or the desktop app started from a pane no longer puts its questions, permission prompts and attention on that pane, or becomes the conversation the pane resumes. With remote input off, someone a session is shared with only watches it, as everyone who comes through Arugula cloud does.

## Changed

- **Remote input off holds for shared sessions too** (#2643). `arugulad sharing remote-input off` makes people who come through Arugula cloud viewers. That now holds whatever is shared with them: a session shared with them or their team as an editor, or their role in the machine's team, no longer lets them type while it's off. Other people's devices are viewers too; only the devices of the machine's own account are as they were. A channel that opened while remote input was on closes when it goes off, and the person's client opens a new one as a viewer.

## Fixed

- **Apps started from a pane keep off it** (#2662). Claude Code's hooks name the pane they run in, and an app started from a pane
inherited that name, so every session in the app used the pane. Now a pane
takes a hook only from the Claude Code in front of it: the one at its prompt,
or in the `tmux` window shown there. Elsewhere, Claude Code asks in its own
dialog. Update `arugula` on the machine for this; an older `arugula` behaves as
before.
