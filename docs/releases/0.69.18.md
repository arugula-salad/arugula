# Arugula 0.69.18

Your agent can see what each agent block it started has spent, in tokens and dollars where the agent reports them, and the total, in list, wait and read_output. An agent session pushes its branch only while its asker and the project's owners and editors can all push to the repo on GitHub, and it never changes workflow files. In a team's context, an agent's new Doc is the team's, in its project on Arugula, and the Doc block reads and fills it there. A ticket, a native issue or a Plane item, can be marked Not finished with what is left, so a merged PR doesn't close it; clearing the mark closes it if a PR already merged. The rail's and the shell's Projects, Docs, Boards and Chat buttons open the project you are in, not every project's pages. The project switcher and All projects still take you out.

## Added

- **Agent blocks say what they've spent** (#2404). `list` shows `spent $1.23 · 45.6k tokens` on each agent block, and ends with the total for the blocks the caller started, with money kept apart by currency. `wait` and `read_output` on an agent block say the same. Codex reports tokens only, so its blocks read `45.6k tokens · cost not reported`.
- **A team's agents write its Docs** (#2402). In a team's context (a repo or issue of a team project, or a team machine) the `doc` tool's `new` makes the Doc in the team's project instead of on the machine, and `fill`, `asset` and the Doc block go there too. Nobody picks where: a personal machine, or one with no control, keeps its Docs as before. Give the machine the Write Docs power over the project (Settings, Access) first; without it the agent is told how, and nothing is kept on the machine instead. With control out of reach the block shows the last Doc it read, read-only. A public link for a team Doc isn't offered yet: `share` gives the team's page.
- **Mark a ticket not finished** (#2408). Some tickets need a second PR, or a check after the first merges. Mark the
ticket from its row's drawer (**Mark not finished…**), or let an agent do it
with `board_write`'s `hold` (and `release`). While the mark is on, a merged PR
that names the ticket still attaches to its row but doesn't close the issue or
move the Plane item to Done, and the row stays in Review with a **Not
finished** chip that carries the reason. **Clear the mark** lets it finish:
if a PR that would have closed it has already merged, it closes then, saying
which PR.

This replaces the "merged, not closed" pill. A row whose PR merged while its
issue is still open and that nobody marked shows the same chip, as "Not
finished · no reason given".
- **Queued PRs say so** (#2415). While a PR is in GitHub's merge queue, its block's state reads Queued, and the strip says it merges when its group passes. If the PR leaves the queue, for example because its group failed, the block shows Open again with Merge. A block on a repo that isn't linked asks GitHub on each poll. On a linked repo, Queued shows once Arugula control tracks the queue.
- **Pop a pane out** (#2428). Chat, a board, a Doc, a PR or any other block can pop out. Its place in the tab says it's in a window of its own, with Bring back, on every screen. In the desktop app the window is a separate window, not a tab of the one it came from. Terminals don't pop out yet: their size is still their tab's.

## Changed

- **Updates check a signed checksum list** (#2403). A daemon release's `SHA256SUMS` now comes with `SHA256SUMS.sig`, signed by the
release key. `arugulad update` and the web notice's *Update now* refuse a release
whose checksum list that key didn't sign. `install.sh` checks the signature too
where openssl has Ed25519 (most Linux), and stops when a release has none unless
`ARUGULA_ALLOW_UNSIGNED=1` (for releases from before signing, or a local build).
On a Mac it checks that the app is signed by Arugula's Developer ID before moving
it into Applications.
- **Session pushes need everyone's GitHub write** (#2395). An agent session in a thread pushes its branch only while everyone who can
steer it may push to the repo on GitHub themselves. That means its asker, the
project's owners and editors, and anyone whose GitHub review was sent to it. When
one of them hasn't signed in to control with GitHub, or GitHub gives them less than
write, the push doesn't go, and the thread names them and says why. Give them write
on the repo, have them sign in with GitHub, or make them a viewer.

**Workflow files.** A session's push no longer writes `.github/workflows/`. A turn
whose commits change a workflow file isn't pushed, and the thread says which files.
A session's agent is told not to change them and to say in its answer what should
change. A session that began before the repo's default branch changed its workflows
can't push either: ask again in a new session.

**Reviews on a session's PR** go to the session only from someone GitHub says may
push to the repo. Anyone else's review gets a line in the thread, and a person can
pass it on by replying.

**A cloud workspace's `GIT_TOKEN`** is used only on the hosts its repos are on when
the token is set. After adding a repo on another host, set it again with
`arugula cloud secret set <workspace> GIT_TOKEN`. A token set before this release
clones nothing until it's set again: `arugula cloud secret ls <workspace>` says
which hosts it's used on, or that it must be set again.

**Session slots** start empty for each session, apart from build caches. A slot
keeps those only for the same person's next session.
- **Arugula keeps you in your project** (#2421). The rail's and the shell's Projects, Docs, Boards and Chat buttons open the project you are in, not every project's pages. The project switcher and All projects still take you out.
- **Boards, Docs and Inbox show your project** (#2423). Boards, Docs and the Inbox open on the project you are in, and its Inbox count is that project's. All projects shows everything again.
- **Chat opens your team** (#2424). Chat opens the team of the project you are in. A link into another team's room says which project it opened, with a way back, and leaving chat returns to your project.
- **Board flags sit on the chip** (#2427). Failed checks show as a red `cloud#16 · checks failed` chip, an agent waiting for input as an accent `waiting for you`, and a stalled agent as an amber `stalled 2h`. A small dot before the title marks a row that needs you, and **Needs you** counts the same rows. A real question keeps its card.
- **Chat's views show your team** (#2425). Activity, Saved, Threads, Search and the unread counts cover the team of the project you are in. Search has All teams for the rest.

## Fixed

- **Node installed after Arugula is found** (#2384). The daemon reads your login shell's environment once, when it starts, so a
Node installed afterwards (nvm, fnm, nodejs.org) wasn't on the PATH it gave
agents' adapters: *Use Claude Code with Arugula* and `arugula setup claude`
kept saying "needs Node 20+" and to install the Node that was there. Now,
when the environment it kept has no Node new enough, it reads the shell
again first; an agent block that can't find Node does the same, so starting
it again works.
- **Busy panes over control's relay cost less** (#2405). A busy pane used to send each small read of its output as a message of its
own, thousands a second, and each one cost control's relay two WebSocket
frames (#856). Through the relay, a machine now sends what a pane wrote in
the last 16 ms as one message; output after a quiet spell, such as a
keystroke's echo, still goes at once. Control also moves relayed bytes on
threads of their own, apart from the ones that wait on its database (#857).
- **Board pills open beside the board** (#2417). A machine's Doc pill on a board block now opens as a block beside the board (or comes forward if it's already open). It was plain text because the shell compared the page's client with the fleet's summary connection, which are never the same.
- **Team default project named as such** (#2418). On a team machine, an agent that files an issue without naming a project now says it went to the team's default project, not your personal one.
- **Plane issues read from the current project** (#2419). forge_read of a Plane issue (IDENT-N) reads it in the current project, as tracker_write and link do, instead of your personal project.
- **Boards by title in the right project** (#2420). board_read and board_write find a board by its title in the project you named or are working in, then in the other projects you reach, and ask which one when two share a title.
- **Linked repos default to the current project** (#2422). Listing and linking GitHub repos without naming a project uses the project you are working in, and linking the repo of a clone no project links yet uses your default project.
- **An agent's images show through Arugula cloud** (#2400). Images pasted into an agent block now show in its transcript on Arugula cloud's page and for people you share the session with as viewers, and a click shows one full size.
- **A Doc link's card in chat opens the Doc** (#2429). A shared Doc's key is the end of its link (`#k=…`), which never goes to a server. Chat's preview cards came from control without it. A card now opens the link as the message wrote it, key included.
