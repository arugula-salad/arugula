# Arugula 0.32.0

## Your team's agents (Labs: `agents`)

- **Delegate to an agent on another machine of yours** (#721). `delegate`
  (MCP), `arugula agents send` and `/api/a2a/delegate` reach an agent this
  machine offers without going through control, as its own account. Leave
  the machine out and the one that offers it is used, this one first.
- **Deliver as a pull request** (#721). With `pr`, the task works on
  `a2a/AGENT-TASK`, branched from its origin's default branch, and is told
  to commit, push and open a pull request with the project's own tooling.
  A `pr` artifact carries the link, and the consent card says so.
- **Run there** (#721): *Run there* in the Team agents block, *Run* on the
  Agents page's Team tab and `arugula agents run` start an agent your
  account offers in its project on its machine, in a session named after
  it, and take you there. A team's other owner can't.
- A task's own caller collects it, this machine's owner included.

## Also

- **A link that's connected but far behind is dropped and reconnects**
  (#713). Every 10 s the page pings the daemon. If 30 s go by with no
  answer, it drops the link and starts again with a fresh hello. This
  isn't checked while the page is hidden.
- **The 0.26 desktop app's events reach the page again** (#708). Opening a
  pane from a notification, and the Daemon menu's *Getting started*, went
  unheard from 0.30.0 on.
- A canceled task that was waiting on its owner no longer ends as
  *rejected* (#719). In Safari, a page that fails to store its keys tries
  again instead of ending in an error (#501).
- The daemon's journal has the panes', the store's and the mux's info lines
  again (#703, #704).
- Inside the daemon: the mux has moved into `arugula-mux` (#704, #705), and
  the GitHub forge and the editor server are cargo features (`forge`,
  `editor`), on by default (#461). Nothing changes for you.
