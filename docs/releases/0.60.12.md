# Arugula 0.60.12

Made as a deploy. Operations only: nothing changes on your machines.

## Hosted control

- **The platform has no volume any more** (Arugula #72, #1440). It has
  run on Postgres since 2026-10-21, and the SQLite file it kept as a
  rollback is gone. The platform now refuses to start without Postgres
  (`ARUGULA_PLATFORM_REQUIRE_POSTGRES`), and its image no longer carries
  Litestream.
- **The nightly Postgres dump can't be starved by deploys** (#1440).
  Each deploy moved the dump machine onto the new image, which restarted
  Fly's daily schedule, so the dump hadn't run since its first night. It
  now runs hourly and skips while the newest dump is under 20 hours old
  (`ARUGULA_DUMP_EVERY_HOURS`).
- **The hub can drop the platform's old copies** (Arugula #71, #1439):
  `arugula-control platform drop-copies --db … --expect window-hub.txt
  [--yes]`. It refuses unless every copied table still matches the first
  window's checksums, and while the platform runs in process.
  Self-hosted controls run in process, so it never applies to them.
- **A release restarts the hub only when the hub changed** (#1441).
  Every release used to redeploy the hub, which briefly drops every
  relayed terminal. Now the control job compares what the hub is built
  from against the release it runs, and skips the deploy when nothing
  changed. The job summary says which happened.
