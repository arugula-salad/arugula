## Added

- **Open a Doc beside a pane** (#2249). A Doc that is already open in a pane, in any tab, comes forward instead of opening a second time.

## Changed

- **Text comes in seven sizes** (#2248). The chat composer on a phone was 13px, which made iOS zoom into the page when you tapped it. It is 16px now, like the other fields.
- **Docs rows are one line** (#2247). Both Docs lists (a machine's and the platform's) drop the line of the Doc's
first text under each title, so more Docs fit in the same height. Search still
matches a machine Doc's opening and every Doc's headings.
- **Docs and the swarm follow the theme** (#2251). A Doc wears the house pair, Slate in dark and Latte in light, whatever palette
you picked, so a shared Doc reads the same for everyone. The swarm and the
getting-started tour take the palette's colours, so Latte reaches them.
- **A Doc's preview, in the house style** (#2252). The bar says when the Doc was updated, how many sections it has and how long it takes to read. Hover it for the words, figures and who made it. Open, copy link and ⋯ are the same buttons as everywhere else.
- **Dialogs and side sheets act the same** (#2253). Every dialog and the board's row sheet sit on the same dimmed backdrop. Escape
closes the one on top and nothing under it, focus stays inside while it is up,
and it returns to what you pressed to open it. A click on the backdrop closes a
side sheet at every width, so on a desktop a click on another board card
closes the sheet first, and a second click opens that card.
- **Words that meant two things** (#2257). Some words on screen meant two different things. They now mean one each:

- The agents strip in a thread said "Idle" for a hosted session that had
  failed or been stopped. It now says Failed or Stopped. Idle still means
  between turns, ready for the next prompt.
- A session card said "done" when a turn ended, though the session takes
  another prompt. It now says "turn ended".
- With no rooms yet, a personal chat said "No threads yet" beside the
  Threads list of replies. It now says "No rooms yet".
- A draft's button said Drop in a pane and Discard on the platform. It says
  Discard in both, and so do the draft's card and a tracker write's.
- The MCP tools speak of a board's lanes, not its zones, and of a Cloud
  workspace's id, not a hosted box's.

A board write takes `group` where it took `zone`, and `zone` still works.
- **A Doc's title sits on a thin line** (#2260). The line under a Doc's title was twice as thick as the one under any other
page's header. It's the house's 1px line now.
- **Every menu is the same menu** (#2261). A message's ⋯ in chat, the Label and Person filters on a board and the pane
menu now look and act alike: icons in a column, a ✓ for the ones you can tick
together (the menu stays open while you pick), and Escape closing the menu
before anything under it. On a phone a menu opens as a sheet from the bottom
with rows made for a finger, and a tap outside it closes it. The board's
work-item picker draws its list the same way.
- **One selected row** (#2254). Sessions, issues, chat rooms, the Docs list, board cards and the phone's sheet
draw the selected row the same way. Settings rows you open are a whole-row
button with hover.

## Fixed

- **Thread readers follow the machine** (#2232). A machine now tells Arugula which panes and sessions it still has, and every
list that changed, so people it takes off a list stop reading the thread. A
list that couldn't be sent goes again on its own, whole, and a list that
arrives late doesn't undo a newer one.

A closed pane's or session's thread keeps the people who could read it when
it closed, less anyone who loses access afterwards: a share taken away, or
someone leaving the team. Nobody new gains it. Someone shared the session
or joining the team after it closed doesn't read it, and nor does someone
who lost access and was given it again.

Once a machine is on this version, only its owner reads the threads of
panes and sessions that closed before the update. The same goes for the
oldest closed ones once there are more than the machine remembers: 2,000
panes and 500 sessions.
- **A removed cloud machine fails its workspace** (#2233). Removing a cloud workspace's machine changed only Arugula control: the workspace still showed ready, and its runs stayed running. Now the workspace fails, saying its machine was removed, and its box is paused until you rebuild or delete it. A rebuild makes a new box and moves the workspace's sessions to it.
- **Closed threads keep the right readers** (#2250). A closed pane's or session's thread keeps the people who could read it when
it closed, less anyone who loses access. Losing access now counts the moment
it happens, even while chat is off, so a share taken away and given again
doesn't bring the thread back. A team's lock keeps its members out only while
it lasts. A pane that closes before the machine knows its team, or while its
enrollment can't be read, gets the team's members and owners once it does,
and nobody else.
- **Deleted GitHub items leave** (#2235). The platform's copy of a linked repo now gets a slow full pass about once a
day. It lists what's open on GitHub and reads again each open item it no
longer lists, so an issue deleted or transferred while its webhook was lost
goes. It also reads again the items it read longest ago, with their text for a
project that mirrors it, so a comment deleted or edited on GitHub catches up.

A deleted item's text goes with it. A read that GitHub refuses for one item or
commit no longer stops the repo's sync. A webhook whose rows fail to write
isn't counted as taken, so a redelivery of it is written; GitHub doesn't
redeliver on its own.
- **Small platform fixes** (#2258). - Removing a board group that holds rows its Plane epic adds is refused, as removing one of those rows is.
- A row's old status from before lanes no longer reaches clients: it reads as none unless the row has an open ask.
- When two rows of one piece of work fold together, their notes join on one line.
- A question to the agent on a thread is matched to the thread's own session or its picked try, never a review or an unpicked try.
- A machine sending an issue's export from its block is refused once the issue is on GitHub, as a send from the page is. The machine still sends the copy it has, not the issue's latest title and body.
- Deleting an account takes everyone's inbox entries on the runs that went with it.
- Deleting a cloud workspace turns off the schedules and event rules of its run specs. Runs already going aren't stopped. A project that chose it for its agents chooses none. Moving a spec to another workspace turns its schedules back on, but its event rules need turning on again by hand on the Runs page.
- **A slow hub no longer stalls PR and board reads** (#2256). The platform used to ask the hub for your GitHub identity on every read of a linked repo's items. It now keeps the answer for at most ten seconds. Linking or unlinking GitHub still shows within a second, because the hub's change feed says so.
- **Board text names ready rows by number** (#2262). The `Ready (n):` line in a board's text view used the rows' internal pointers
(`iss_740b34d7`); it now prints the same `#N` the rows below it do.
