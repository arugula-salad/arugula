# Arugula 0.65.0

Three things are new here.
- **The last of feature discovery's waves** (native #238): what only the CLI could do with cloud workspaces, runs and agents now has a place in the UI, and eight more hints point at features where they're useful.
- **A wave of agent sessions is something you can follow.** The Sessions page lists a project's sessions with their branches and what waits on you. Your agent can wait on a wave and read each answer whole. The pool spreads a wave across the boxes, and a session can work in a linked repo no box has cloned.
- **Boards hold proof:** a row in a board's PROOFS zone can point at a link, and it shows as proven when its link, run or merge says so.

Under the hood, the daemon split went on (steps 10–18), and panes keep everything they printed across a stop or an upgrade.

## New

### Feature discovery, wave 4

- **Cloud workspaces and runs, without the CLI** (#1721, native #260). A workspace's page has **Edit** (repos, setup, size), **Rebuild**, **Public previews**, **Secrets** and **Inference keys**, beside what it showed before. Each uses the operation `arugula cloud` calls. Owners and editors can use them; others are told why they can't. A run spec's page lists its **schedules and event rules** and adds or removes them.
- **The agent dialog's More** (#1721, native #260): the options only `arugula agent` had (`--permission-mode`, `--mcp NAME=CMD`, `--allow TOOL`, `--user-settings`). The defaults are unchanged.
- **The Claude Code plugin** is offered wherever hooks are (Getting started's Agents step and the unhooked-Claude chip), with the two `/plugin` lines to copy (#1721).
- **This machine › Agents' grants…** shows what the machine's agents may do on control (threads, issues, runs, deploys, `cloud.drive`), with a link to Settings to change it (#1721).
- **Hints, batch 2** (#1721, native #261, decision aru-118). Each appears once per account, behind Tips:
  - a command's first mark: right-click it to copy its output or run it again;
  - the Share dialog's warning that a pane may show secrets: **Make this pane private**;
  - a commit in a pane: see what changed beside it;
  - vim or `code` in a pane: open the editor beside it;
  - another machine in the host menu: split a shell on it;
  - push turned on through control: choose what to be told about;
  - a shared session with agents in it: get told when they need someone;
  - a GitHub-only account on a device that makes passkeys: add one.

### Agent sessions, as a wave

- **The Sessions page** (#1721, native #267). Under a project, it lists its sessions newest first: state, issue, box, branch and HEAD, last push, who started each, and what waits on you (a question, a permission, CI that failed again, a PR to send). Narrow it by label, tracker (the issues an issue's body names), asker, or what's still going. An open issue's card now appears without a reload.
- **Your agent follows a wave** (#1721, native #267). The MCP tool `list` has the kind `sessions`, and `read_session` reads one session whole: its turn's commits, its diffstat, and its last answer in full (the thread keeps only its end). `wait` with `session` waits until any of them finishes its turn. They need your person's `sessions.start`, `sessions.reply` or `threads.read` grant.
- **The pool spreads a wave** (#1721, native #266). It wakes an idle box rather than put another build on a busy one. The box picker's counts leave out sessions from before a rebuild.
- **Sessions in a linked repo** (#1721, native #268). A session on a repo linked to the project but missing from its box's setup clones it at the start: shallow, at the default branch's head, with a token control mints for that clone. The box revokes the token after.

### Boards

- **Evidence on PROOFS rows** (#1607). A board row can point at a link (https only). A row on a run shows the run's live state to those who may read it. A row in the proofs zone shows as **proven** when it points at a link, a succeeded run or a merge. `board_write add_row` takes a link.
- **Board grants** (#1708): a Boards column (off, read, read and write) in a machine's grants in Settings, and `boards.read` and `boards.write` among an agent token's powers.

## Changed

- **The daemon split, steps 10–18** (#232: #1685, #1688–#1690, #1692, #1697, #1698, #1710, #1713, #1717). New crates: `arugulad-forge`, `arugulad-review` (the diff and file blocks), `arugulad-invite`, `arugulad-hosted` and `arugulad-control-tools`. The hosted box, MCP's control tools and the agent block's surface now go through registries. Nothing changes for people.
- **For contributors** (#1721, native #269):
  - `just rollup-check` runs CI's check locally and gives one verdict;
  - check also runs on `merge_group`;
  - the platform page embedded in debug builds reruns when `web/dist-platform` changes;
  - `just dev-control` works over the tailnet.
- **CI** (#1691, #1694–#1696, #1700, #1707, #1711, #1716, #1718, #1719): flaky tests fixed (the test stack, macOS's agent block and sessions, chat, Docs, perf budgets); main's gitleaks scans main's own history; quarantine refuses a test in a serial spec.

## Fixed

- **Panes keep every byte across an upgrade or a stop** (#1686, #1705). At a shutdown, a pane's reader stops before its checkpoint. What it read goes into the log, and what it hadn't read stays in the terminal for the next daemon. When nothing keeps the terminal (a daemon run by hand), the rest is read into the log first.
- **The desktop app** opens Chat and Projects in the window that's showing it again, below macOS's tab strip (#1699).
- **Journeys J2a and J2b** no longer stop at "Allow the app" while Getting started closes (native #280).
