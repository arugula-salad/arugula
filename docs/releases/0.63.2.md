# Arugula 0.63.2

Link GitHub to an account you're already signed in to, and the first steps of live status boards, behind a Labs flag.

## New

- **Link GitHub from Sign-in and account** (#1553, native #208). An account signed in without GitHub (with a passkey, say) can now link one: **Link GitHub** goes through GitHub's account picker and adds it to the account you're signed in to. It never makes a second account or changes your sign-in. Once linked, GitHub signs you in to that same account, and the row shows its login with **Unlink**.
  - A GitHub account that already signs in to another Arugula account isn't linked, and the dialog says so. Accounts are never merged.
  - Unlink is refused while GitHub is your only way to sign in: add a passkey first.
  - A link counts only in the browser and sign-in that started it, and GitHub's token is revoked as soon as it's read.

### Labs: boards

Behind the new `boards` Labs flag, for trying internally. With it off, nothing changes and every board route is a 404.

- **Boards** (#1528, #1551, native #187, #188): a project's live status board, with zones and rows that point at PRs, native issues, runs, cloud workspaces or agent blocks. Each row has a one-line note and a status. A PR's or an issue's row shows its live state (checks running or failed, merged, closed) and redraws as it changes. A board has its own page, at phone width too, and a board block shows one beside a pane.
- **Agents on boards** (#1552, native #189): `board_read` and `board_write` over MCP, with the `boards.read` and `boards.write` grants (`arugula grants add`). An agent can add rows and set a row's note and status, but it can't change zones, repoint a row, or remove a row another machine added.

## Note

- The platform gains migrations `0053_boards` and `0059` (`board_entries.agent`), and runs them whether or not the flag is on.
