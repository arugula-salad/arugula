# Arugula 0.64.1

Machines can update to this release. 0.64.0's daemon called itself 0.0.0, so `arugulad update` refused it. This release also fixes a chat message that could go missing, and a daemon that could stop when a client hung up.

## Fixed

- **Updating to this release works** (#1667, native #279). Since the daemon became a thin binary over `arugulad-base` (#1631), `arugulad --version` said `arugulad-base 0.0.0`. `arugulad update` checks the version of the build it downloads, so it refused 0.64.0 with "says it's 0.0.0, not 0.64.0". It now says `arugulad 0.64.1`, and a test holds it to the release. Machines on 0.63.x skip 0.64.0 and update straight to 0.64.1.
- **A chat message that arrived while the page was fetching the room is no longer missed**, and two more chat races are closed (#1657, native #217).
- **The daemon survives a client hanging up mid-request**, and hosted work notices a session that joins early (#1660).

## Changed

- **Daemon split, steps 7–9** (#1663, #1664, #1671, #232): Labs' surface in the daemon is a trait, the gates and the Forgejo/GitLab connectors live in Labs, and Labs is a crate of its own (`arugulad-labs`). Nothing changes for people.
- **Tests and CI** (#1669, #1670, #1682): `just test-stress` shows a flaky test's fix holds, and the forges and macOS nightlies wait on the right things.

## Note

- The desktop app's fixes from the same days (the keychain prompt after an update, links to Control) are in app 0.31.0 (#1665, #1666).
- No migrations.
- Every machine updates to 0.64.1 as usual, from 0.63.x or 0.64.0 alike: the check reads the downloaded build's `--version`, and 0.64.1's is right. A cloud workspace built on 0.64.0 gets 0.64.1 when it's rebuilt.
