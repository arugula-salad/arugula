# Arugula 0.35.0

Approvals carry a secret instead of a fingerprint to compare (#765):
joining a machine, signing in the CLI or the desktop app, approving a new
browser or phone, and inviting someone to a team no longer ask you to
check that two strings of hex match. A synced passkey brings a browser
back as the same device. Also: palettes, finishes and corners, and each
machine says whether it's yours or a team's.

## Nothing to compare

- **Joining a machine or signing in the CLI** (#760): the link `arugulad
  join` prints carries a secret after its code (`#join=CODE.SECRET`).
  Approving answers it, and the machine finishes by itself: no account
  fingerprint to type. Typing the code works too (the fixed part, then the
  rest). An older daemon or CLI still joins the old way.
- **A new browser or phone** (#761): it shows a code and a QR code. Scan it
  from a device you already use, or type it there, and it's approved, with
  nothing to compare. An approving tab left open from before still works;
  the new browser then asks you to check the account.
- **The desktop app's sign-in** (#758): no code. *Allow* in the browser
  makes the app a device of your account.
- **Team invites** (#762): every link carries a one-time key, *Ask me
  first* ones too, so an owner admits someone without a fingerprint.
  **Ask me first links and pending requests from before are dropped**:
  ask for a new link. An old `#invite=` link says so.
- **Sharing with a person** (#763): their key is pinned the first time you
  share. If it changes, sharing stops and says since when. *Verify* is
  optional, and marks the person ✓.
- **Devices are named by kind and dates** (#759); fingerprints are behind
  *Details*.

## Passkeys

- **A synced passkey brings back the same device** (#764): a passkey with
  PRF (iCloud Keychain, Google Password Manager, …) derives this browser's
  keys, so clearing site data, or the same passkey on another computer,
  is the same device with no approval. Removing that device sends the
  passkey's browsers back to being approved one by one.
- A recovery code approves a passkey's new device (#791).

## Appearance

- **Appearance…** in the account menu (#776): eight palettes (and *Match
  system*), each with its terminal colours; Flat, Aqua, Brushed metal and
  Glass finishes; Square, Soft and Round corners. Saved per browser.

## Also

- **Each machine says whether it's yours or a team's** (#778): in the
  host menu, *Devices and machines…* and before joining one to a team.
- `docs/journey-steps.svg`: each journey's steps by station, and what no
  journey reaches yet (#775).
- `just dev-control` signs in as other logins and serves passkeys on
  localhost; `just dev-browser` screenshots it (#774).
- No binaries in the repo: `scripts/check-binaries` on every PR (#786).
