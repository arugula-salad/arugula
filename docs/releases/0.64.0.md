# Arugula 0.64.0

Two things are new here.
- **The last wave of feature discovery** (native #238): search everything your panes printed from command search, see and revoke the links and guests you've shared, and see what your agent can do for you.
- **Your agent can run agent sessions for you.** With two grants you give it, it starts them on your project's cloud workspaces and answers their questions. The dev boxes those sessions run on start from a fresh main and can run their own browser tests.

Under the hood, `arugulad` is now a thin binary over feature crates.

## New

### Feature discovery, wave 3

- **Search output…** in command search (#1645, native #245). It searches every pane's output on this machine and the other machines the page talks to, as plain text ignoring case, with up to 50 hits a machine, newest first. Picking a hit opens that pane at the line, or says it has left the scrollback. Search is for owners only.
- **The Share dialog lists what you've shared** (#1645): live read-only links and ssh guests, each with **Revoke**, which takes effect at once, and this session's **Access log**.
- **All sessions in the Activity drawer** (#1645): every session's history, including closed panes, the way `arugula history` reads it.
- ***What your agent can do here*** (#1645, native #246). Every MCP tool has a plain-words line and an example prompt. The daemon serves the list filtered by what this machine offers. It shows in Getting started's Agents step, in the Start-an-agent dialog (click an example to use it) and on the Docs page.

### Agent sessions, run by your agent

- **Agents start and answer sessions, by grant** (#1658, native #265, decision aru-121). Two project grants, **Start sessions** (`sessions.start`) and **Answer sessions** (`sessions.reply`), let a machine's agents act for its owner:
  - start a session on an issue or thread, through the MCP tool `session_start` or an `@arugula` it posts;
  - answer the session's open question, or send it a prompt, through `session_reply`.

  You stay the asker and the one who pays. The card says "Started by <you>'s agent on <machine>". A reply never approves a permission. Without the grants nothing changes. Give them in **Settings › Agents** or with `arugula grants add <machine> sessions.start sessions.reply --project <project>`.
- **Sessions start from a fresh main** (#1658, native #263). A session's branch starts from the default branch as fetched when the session starts, not the box's clone from setup. If the fetch fails, it falls back to that clone and says so.
- **Dev boxes run browser tests** (#1658, native #264). The example dev-box setup (`packaging/hosted/examples/arugula-dev-setup.sh`) installs Playwright's Chromium and one lock per box. `just e2e-spec SPEC…` runs one spec under it. Sessions are asked to run the tests and specs they wrote and report how they went, and not to commit generated files.

### Docs

- **Shared Docs say they're Arugula's** (#1632): a footer, the leaf icon, a link preview and Arugula's fonts.

## Changed

- **`arugulad` is a thin binary over crates** (the daemon split, #232: #1631, #1637, #1639, #1649, #1655, #1656). The new crates are `arugulad-base`, `arugulad-editor` (the editor and Claude Code's IDE), `arugulad-drivers` (deploy drivers) and `arugulad-docs`. Feature crates now handle their own operations and add their own MCP tools. Nothing changes for people; a change to one feature now rebuilds less.
- **CI** (#1633, #1636, #1640, #1641, #1644): lint runs on pull requests, flaky tests can be quarantined with an expiry, the e2e shards run on GitHub's runners, and Postgres tests run without fsync in a job of their own.

## Fixed

- **A box's daemon fixes `/etc/resolv.conf`** at start, after a resume and before each session's prompt (#1658). The sandbox writes the file without a trailing newline, and Zig, which builds libghostty, can't read it that way.
- **The desktop app** opens a link to the platform page in the window that's showing it (#1629).
