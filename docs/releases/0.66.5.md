# Arugula 0.66.5

Each agent conversation in a channel reaches its own session, and chat's @ picker offers machines and their sessions. Boards keep themselves current: a merged PR closes its issues and moves its Plane tickets to Done, and one piece of work is one row however many places it lives. Plane writes take names, and each connection decides which agent writes need approval. Merge asks for a confirm click, and focus view no longer traps the phone. Update every machine.

## Changed

- **Each conversation reaches its own session** (#1918, #429). A reply in a thread goes to the session that posted in that thread, not to whichever agent on the machine posted last. An agent's post names its session ("alecraso's agent on Aarons-Mac-mini · UX Improvements"). `@machine/session` reaches just that session. When the session that started a thread has ended, the room's last poster gets the message and is told why.
- **Machines in the @ picker** (#1921, #428). Typing @ in chat lists people, then the machines whose agents hear the room, each with its owner and an online dot, and the sessions that posted there this week under it. Picking a session inserts `@machine/session`. A machine mention that reached its machine shows as a chip with the machine's icon.
- **A merged PR closes its issues** (#1926, #432). A merged PR closes the native issues it names: `Arugula #N` or `(#N)` in its title, its branch (`feat/N-…`) or its body, and the issue of a board row it was attached to by hand. No keyword is needed. `part of Arugula #N` links without closing, and the issue's timeline names the PR.
- **A merged PR moves its Plane tickets to Done** (#1930, #437). A Plane item a merged PR names (`ARUGU-12`) moves to its project's first completed state. This runs after the PR's issues close, so a slow Plane never holds up GitHub, and it retries for about half a day. `part of ARUGU-12` links without moving.
- **One work item per piece of work** (#1908, #405). A native issue, its GitHub copy and a Plane item for the same work are one row on a board, never two. Every item has a status category: triage, backlog, unstarted, started, completed or canceled.
- **Lanes follow Plane's states** (#1913, #424). In Progress is Doing, a started state with "review" in its name is Review, and Cancelled is Done with a "cancelled" mark that never counts as proven. A native issue closed as not planned gets the same mark, and so does a GitHub issue (#1923, #433).
- **A bare `#N` on a board is the project's own issue** (#1922, #436), even when a linked repo has its own #N.
- **Plane writes by name** (#1909, #422). `tracker_write` create and edit take a state, module, type and labels by name, and a parent as `ARUGU-12`. An unknown name is refused, and the answer lists the real ones; `forge_read tracker_fields` lists them too. Reopening goes to the project's default state.
- **Approval per kind of Plane write** (#1914, #423). Each Plane connection sets allow or approve for agents' creates, comments, edits, state changes and field changes, with three presets. New connections default to "Allow comments and edits, approve creates and closes". The footer an agent's write carries is full, short ("— via Arugula", the new default) or none.
- **Plane docs** (#1915, #425). docs.arugula.io/plane/ and /plane-agents/ are live, and `tracker_write` and Settings → Plane link to them.
- **Board cards at mid widths** (#1912, #426). A card's title keeps a readable width, its state chip wraps under the title, and "proven" moves to the line below. A board two to four lanes wide shows two lanes per row, laid out by the board's own width, so a board in a pane works too.
- **Merge asks for a confirm click** (#1917, #427). Picking a method from Merge ▾ turns the button into "Confirm squash" (or the method you picked), and only that click merges. Escape, a click elsewhere or 5 seconds take it back. Drafted merges are unchanged: their Send is the confirm.

## Fixed

- **Merge ▾ offers only the repository's methods** (#1917, #427). A squash-only repository's PR block offered every method when the block hadn't asked yet, and a pinned block (a linked repo, read through control) never asked. Control now reads them with its GitHub App, and until the answer comes the block offers only the forge's default.
- **Focus view no longer traps the phone** (#1933, #439). Focus belongs to the screen holding the tab: another screen taking the tab, or a tap on another pane on the phone, ends it. A focus stored before this update is ignored, and a reload ends a focus.
- **Mentions of other people** (#1937, #438). A mention of someone else showed as dashed, "This reached no one", to everyone but that person. It's a normal chip when it reached them; only a name that matches no one is dashed.
- **A run's kept log** (#1916, #161). It ended with the terminal's own "[exited with code 0 · press Enter for a shell]". It now stops at the program's last output.
- **Older daemons read boards again** (#1910). Control 0.66.4 sent a block-state field that 0.66.3 daemons refused, so `board_read` and `board_write` failed on boards with a live agent block. Daemons now ignore fields they don't know in control's answers (#1920, #431).

## Note

- **Upgrade:** existing Plane connections keep their approval level (allow becomes all allow, approve becomes all approve), but their footer switches to short.
- The platform migrations **0080_work_items**, **0081_tracker_fields**, **0082_tracker_write_policy**, **0083_chat_agent_session** and **0084_forge_state_reason** are all additive.
- Merge ▾'s methods for a pinned PR and #429's session routing need both control and the daemon on 0.66.5.
