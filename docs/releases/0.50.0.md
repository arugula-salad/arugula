# Arugula 0.50.0

The daemon no longer keeps chat (#1099, M125, part of #978). Control holds
all of it, as 0.49.0 began. The daemon loses about 7,900 lines.

**Breaking:** chat without control is gone. A machine that isn't in
control, or one whose account or team has control's `chat` flag off, has
no chat at all: no threads on panes or sessions, no conversations, no
Chat page that works. If you used chat on a machine on its own, it stops
working on this version. Your old threads stay on disk, unread, until the
machine joins control with chat on.

## Chat needs control

- Threads, conversations, the Chat page and mention pushes all come from
  control now. The daemon keeps no messages and serves no `/api/threads`
  or `/api/convs`.
- A machine with the `chat` Labs flag but no chat in control still shows
  *Chat*, and its page says **Chat needs control** (or, signed in to
  control, that chat is off for you there). This is what a page the
  machine serves itself shows. The flag now reads "The chat page, which
  needs control. Brings this machine's old threads into it."
- Who may read a pane's or session's thread is still the machine's call:
  it tells control (the people it shares the pane or session with, from
  when they were shared, and its owner).
- An older daemon's link to a thread (`&thread=`) still opens the pane.

## Old threads still come in

- A machine that skipped 0.49.0 still brings its pane and session threads
  and its conversations into control when it upgrades, joins control and
  has the flag on. It reads them from `threads/` on disk, posts them once,
  and moves the folder to `threads.imported/`, as 0.49.0 does.
- A machine not in control leaves `threads/` where it is.

## Gone for now

- **Inviting someone you @mention.** The daemon used to offer an owner to
  invite whoever an `@` mention named who couldn't read the thread (#297).
  Control's chat doesn't offer it yet; #1113 brings it back there.
- Thread hits in the daemon's `/api/search` and in MCP `history`.

## For whoever runs control

- Nothing new to deploy for this release beyond the usual: control
  already holds chat since 0.49.0. Keep the `chat` flag off until the
  privacy notice for chat is published; with it off, machines on 0.50.0
  show *Chat needs control*.

## For contributors

- The wire lost `ServerMsg::Thread`, the thread and conversation types and
  their ten ops; `web/src/shared/proto.gen.ts` is regenerated.
- `chat.spec.ts`, `threads.spec.ts`, `chat-messages.spec.ts` and
  `chat-convs.spec.ts` are gone; `chat-control.spec.ts` covers chat, and
  `labs-off.spec.ts` checks the needs-control page.
