## Added

- **Share a Doc with a team** (#2265). A Doc a machine made already has a read-only copy on the platform, in your
own project. Share with…, on that copy's page and in the machine's share
dialog, picks one of your teams' projects and makes a new Doc there from the
copy's title, sections and pictures as they are now. The team owns it and
edits it like any Doc; the Doc on your machine stays as it is, and is still the
truth for itself. The team's Doc says which Doc it was made from.

Nothing is live. When the Doc on your machine changes, Update copy (beside the
project's row) replaces the team's Doc with the copy again, and asks first if the
team edited it since. Only you can share your copies, and only into a project
where you can make Docs.

## Changed

- **Cloud workspace help says machine** (#2264). `arugula cloud create`, `edit`, `secret`, `rebuild`, `delete` and `key` said
"box" for a Cloud workspace's machine, a word that also means hud and studio
app boxes. Their help says "machine" now, and so do the line `cloud secret
set` prints and `arugula access`' line for a deploy's or a snapshot's
machine. `arugula grants`' help said boards.write never makes or deletes a
zone, which was wrong: an agent makes groups. It now says what's true: the
agent never sets a lane, and deletes or repoints only the rows its machine
added. Nothing else changes.
- **The app's text is Instrument Sans** (#2266). Chat's composer and the fields follow it. Their size is unchanged: fields stay 16px on a phone, so tapping one doesn't zoom.
- **One empty, loading and error look** (#2255). Every page, pane and block now says "nothing here" the same way: a dashed card with a title, a line on what the thing is, and at most one button. A list that can't be read says "Can't…" with Try again, and a loading line waits a third of a second so a quick load doesn't flash it. On the phone, Here with nothing waiting says "Nothing right now."

## Fixed

- **Exports and inbox marks hold up** (#2237). Opening a native issue on GitHub now records the GitHub link in the same step
that marks the send done, and only for an issue in the draft's repo. Before, a
failure between the two left the issue with no link, and a second export could
open a duplicate GitHub issue. A new export is also refused while another of
the same issue was sent, while a send whose issue couldn't be taken for its own
stands (it may be on GitHub as that, and can't be linked, so the message says
discarding the draft may open a second GitHub issue), or when a send that never
finished may have opened an issue with its title already. A duplicate is still possible if GitHub
opens the issue and the platform stops before it hears back, until the mirror
sees that issue.

An issue already on a board also joins its GitHub copy at once, so a PR that
closes the GitHub issue attaches to the board's row.

The inbox drops an entry only when GitHub clearly says you can't read the
repo. An error, a rate limit or a garbled answer from GitHub used to count as
"no" for ten minutes, which deleted your entries with their seen and done
marks.
- **Tapping an agent's composer on an iPhone no longer zooms** (#2267). An agent's composer is 16px on a phone, like every other field, so tapping it on an iPhone no longer zooms the page.
