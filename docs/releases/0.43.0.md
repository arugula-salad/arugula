# Arugula 0.43.0

Arugula can now send usage counts and crash reports, if you say yes.
Nothing is sent until you do.

## Usage and crash reports, opt-in (#989)

- **Asked once.** The first `arugula` command you run at a terminal
  asks. So does the web client and the desktop app, with a card in the
  corner. Control's page asks about your account, then about each
  machine you own. If you don't answer, it stays off. `arugula telemetry
  on|off|status` (or `arugulad telemetry …`) changes your answer, and so
  does *Usage and crash reports…* in a machine's settings.
- **What's sent.** Your version, OS, processor and how you installed
  Arugula. Once a day: how many terminals, agents and blocks you opened,
  which views you used and which Labs flags are on. For a crash: the file
  and line in our code, and our functions on the stack. Everything sent is
  a number or a value from a fixed list. It never includes what your
  terminals show, file names, commands, prompts or a panic's message.
  `arugulad telemetry status` shows the next report exactly as it would
  go, even before you say yes.
- **Where it goes.** To the hosted control, which passes it on to
  product analytics. A machine joined to the hosted control signs its
  report. Any other machine sends it unsigned, under a random install id.
  Saying no deletes the id, and any counts and crashes not yet sent.
- **Always off** while `DO_NOT_TRACK` is set, `ARUGULA_TELEMETRY=off`
  is set, under `CI`, and in test runs.

[telemetry.md](../telemetry.md) has the details, and the
[privacy notice](https://arugula.io/privacy) has the rest.

## Control

- Control now keeps each joined machine's version, OS and processor,
  which it sends when it connects.
- `POST /api/telemetry` takes installs' reports, and `/api/me/telemetry`
  holds your account's answer for control's page.
