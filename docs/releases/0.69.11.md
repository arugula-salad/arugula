# Arugula 0.69.11

The platform mints an agent session's push token only when the person who asked for the session can push to that repository on GitHub right now. Signing up with a passkey that already belongs to an account is refused with a clear message, and a sign-up that doesn't finish leaves no account, identity or passkey behind. A mention an agent block was working on, or had waiting, shows as dropped when the block is closed, instead of "working on it" for good. arugula status no longer points at the journal when the daemon isn't a systemd service, and the daemon's log file has no colour codes or a warning about chant. Turning Guest SSH access off now also ends every ssh invite and cuts off anyone using one, and any invite can be revoked whatever the setting.

## Changed

- **A session pushes only for someone who can push to the repo** (#2341). An agent session on a hosted box pushes its branch with a token the
platform mints for that one push. The platform now mints it only when
the session's asker could push to the repository themselves: it looks up
the asker's GitHub account and asks GitHub for their role on the repo at
each push, and a role below write, no linked GitHub account, an asker
whose account is gone, or GitHub not answering means no token, with the
reason in the box's log (for example, that they can't push to
`OWNER/NAME` on GitHub). The token still writes the repository's contents
and workflows, as before, so a session begun before main changed CI can
still push; the asker's own GitHub access now bounds that. A clone of a
linked repo at a session's start is unchanged.

## Fixed

- **Passkey sign-up refuses a passkey that's already registered** (#2343). Signing up with a passkey that already belongs to an account is refused with a clear message, and a sign-up that doesn't finish leaves no account, identity or passkey behind.
- **Closing an agent block drops its mentions** (#2351). A mention an agent block was working on, or had waiting, shows as dropped when the block is closed, instead of "working on it" for good.
- **A fresh install's status and log say less that's wrong** (#2354). arugula status no longer points at the journal when the daemon isn't a systemd service, and the daemon's log file has no colour codes or a warning about chant.
- **Turning guest SSH off ends its invites** (#2352). Whether it's turned off in the machine's *Guest SSH access…* or with `arugulad sharing guest-ssh off`, every ssh invite ends within a second, anyone using one sees "Guest SSH access was turned off", and the guest ssh server stops listening. Turning it on again brings none of them back.

`arugula guests` and `arugula guests revoke ID` work whether the setting is on or off; only making an invite needs it on.
- **A prompt reaches an agent woken by a background task** (#2353). Claude Code took a prompt that came in the middle of that work into it and never
answered it, so the agent block waited on it for good, and everything queued
after it waited too. The prompt now goes as a turn of its own once the agent is
done.
- **Prompting an agent clears the daemon restart card** (#2353). After a daemon restart cut an agent's turn off, prompt_agent and `arugula send --wait` send the prompt and clear the card, instead of saying the agent waits on a question it doesn't have.
- **A reply on a board's thread reaches who asked** (#2356). An agent's session that asks a question on another board's thread hears the
answers given under it, by name, as the board's lead hears posts there. If that
session has ended, the reply waits in its machine's inbox. A reply under your
own post doesn't come back to you.
- **A slow control no longer reads as a missing grant** (#2355). `capabilities` used to say a tool was `not_granted`, with the
`arugula grants add` command to fix it, whenever control didn't answer the
grants read in time, right after a daemon restart, say. Now it says
`unreachable` and to try again shortly. Only an answer from control without
the grant says `not_granted`.

`wait` on agent sessions or on a run asks control again and again until its
timeout. One ask that went unanswered (a dropped connection, a timeout) used
to end the whole wait with "can't reach Arugula control". Now it asks again,
and a wait that runs out says "still running", as it does when nothing went
wrong. When control doesn't answer, the daemon's log names the cause.
- **An issue export names who wrote each comment** (#2358). Comments nobody here wrote (a session's card, "CI failed …", what a session
said, a comment from GitHub on an issue opened there) are named as the
issue's page names them. "a deleted account" is left for someone who deleted
theirs. The JSON export keeps each comment's raw `via` beside its `author`.
- **A first visit to a machine's page is quieter** (#2359). On a machine's own page, the card asking about usage reports no longer sits
behind Getting started's greeting: it shows once no dialog is up. Getting
started's *Edit in nvim* card names itself once, and says "Nothing to install"
only when the daemon finds `nvim` on its PATH; otherwise it says nvim is
needed. As the page loads it asks whether control serves it, and a daemon now
answers 404 rather than 401 (which also logged a rejected request each time).
- **Your agent knows your chat post is yours** (#2357). Before, every chat message reached an agent labelled as a teammate's, even
its own owner's. Now Arugula control tells the machine when its owner wrote
the post themselves, signed in as the account that owns it. Anyone else, and
every agent, your own agents included, is still a teammate. Replies of one
thread that arrive together each say whose they are. A machine on an older
Arugula, or an older control, keeps calling everyone a teammate.
