# Arugula 0.46.1

Follow-ups to 0.46.0's new workspace: the activity drawer keeps its System
events, editors match the palette, and many terminals at once no longer hang
the page.

## The workspace

- **System activity survives a reload** (#1035). A pane opening, exiting or
  closing and a machine coming or going are now kept by the daemon, in one
  log of about 2 MB, so the activity drawer's *System* shows the last day's
  after a refresh, and through control too. `/api/events` replays them
  without `follow=1`, with the same ids the live stream gives, and a closed
  pane's events still answer `session=`.
- **Editor blocks follow your palette** (#1048). An editor pane takes the
  page's colours (Slate by default, a light palette's in a light one) and
  changes with them, without a reload. On a shared block, whoever last opened
  it or changed palette sets its colours. A theme you chose yourself in the
  editor's settings is left alone. An editor in a VM keeps the extension's
  theme.
- **Many terminals at once** (#1049). Opening several tabs quickly could flip
  between two of them forever and stop the page answering; it no longer
  does. At most 12 terminals draw with WebGL (the ones shown or focused
  last), the rest with the DOM renderer, and a lost WebGL context falls back
  to the DOM renderer at once instead of a blank pane.

## The editor extension 0.2.2

Three themes: **arugula** is now Slate (the web client's default), **arugula
light** is Latte, and **arugula mocha** keeps the old look, with its dim text
a little lighter to read.

## Upgrade notes

If you used the extension's *arugula* theme in desktop VS Code and want the
old colours, pick *arugula mocha*.
