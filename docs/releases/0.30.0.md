# Arugula 0.30.0

## Your team's agents (Labs: `agents`)

A new Labs flag, *Agent catalog* in Developer settings (`arugulad flags
agents on`), lets one person's Claude Code agents hand work to another's
(#403).

- **Recipes are Claude Code subagent files** (#398). Arugula reads
  `.claude/agents/NAME.md` in a project, or in `~/.claude/agents/`, as it
  is. `arugula agent --as NAME` runs one in an agent block. It brings the
  recipe's prompt, model, tools, permission mode and skills, which are
  preloaded as Claude Code does for a subagent. It also brings its MCP
  servers, with credentials passed by reference and nothing else: no
  account connectors. Fountain's `--as` is now `--as-fountain`.
- **Offer one to your team** with `arugula agents offer NAME` or from the
  *Team agents* block. Each offered recipe is an A2A 1.0 agent card.
- **The team's catalog** (#399): *Team agents…* in the menus,
  `arugula agents catalog`, or MCP `list {kind: agents}`. It lists every
  agent offered on your own machines, your teams' machines, and
  teammates' own machines that offer something, each with its owner. A
  machine that's offline shows its agents as last seen. Your machine reads
  the cards itself, through control's relay with its own key, and control
  never sees them. A machine reaching another for agents gets those agents
  and nothing else.
- **Delegating** (#400): an agent uses MCP `delegate` to send a task, and a
  person uses `arugula agents send MACHINE AGENT TEXT`. The task runs as
  the recipe in a git worktree on the other machine, where its people can
  watch it and answer its permission prompts. It returns a reply and a
  patch, and its questions come back to whoever sent it.
- **Consent** (#401): a task from someone else waits until that machine's
  own account allows it, on a card that's also pushed to your phone. The
  choices are *Allow once*, *Allow for an hour* or *Deny*. A team's other
  owner can't allow tasks on a team box for you. Hour-long grants are
  listed with *Revoke* (`arugula agents grants`), and tasks survive a
  restart.
- **The work comes back reviewed** (#402): `delegate {kind: review}` (or
  `arugula agents review TASK`) shows the patch in a diff block on a copy
  of your checkout. `{kind: apply}` (`arugula agents apply TASK`) applies
  it with a three-way merge, and says which files changed, what
  conflicts, and what the task left out.

Using this between people needs this release on both machines. Hosted
control already has its part.

## Agents

- **A turn a restart cut off asks to continue** (#680): the block comes back
  with a note and a card offering *Continue* or *Dismiss*, and
  `arugula wait` reconnects across a daemon restart.
- **Background work** (#681): an agent whose turn is done, but whose
  adapter waits on a background task, shows idle instead of working, so
  `arugula wait` returns. An agent woken by a finished background task
  shows working until that's done.

## Also

- **The rename's bridges are gone** (#534): every install is on 0.26 or
  later, so the `illogical` names (variables, headers, links, services,
  downloads) are no longer kept. On upgrade, Claude Code hooks and MCP
  servers still registered under the old name are renamed for you.
- `arugula … | head` and `arugulad flags | grep -q` end quietly on a closed
  pipe instead of panicking (#682).
