# Arugula 0.56.0

Step 3 of the platform roadmap (#1171): the web app is split in two. The
page that holds your device keys, control's page (the "shell": machines,
terminals, blocks, the swarm, devices and teams), is now separate from the
page that holds the team's work: projects, chat and Cloud workspaces, at
**app.arugula.io**. Scripts on the platform page can't use a device key, and
CI proves its build loads none of the code that does.

## The platform page

- **Projects, chat and Cloud workspaces at real addresses:** `/p/<project>`,
  `/p/<project>/chat/<room>`, `/dm/<room>`, `/p/<project>/workspaces/<id>`,
  `/agents`, `/settings`. Each id has the name after it for people
  (`/p/prj_…-acme`); only the id is read, so a rename never breaks a link.
- **A project's home** lists its channels, its Cloud workspaces and its
  team (read only; the team is changed on control's page, where a device
  signs it). A project switcher sits in the bar.
- **Signing in is one silent redirect** through control: someone signed in
  on control's page sees no prompt. Passkeys stay on control's page.
  Signing out there signs the platform page out at once.
- It ships with the platform, so a fix there needs no daemon release.

## Control's page

- Chat, Cloud workspaces, Cloud agents and Plan and usage open on the
  platform page. Cloud workspaces leave the sessions sidebar for a link.
  Threads on panes and sessions stay where they are.
- **Old links keep working, forever:** `#chat=…`, `#cloud=…` and
  `#cloud-ws=…` (bookmarks, notifications, links from older machines)
  land on the same room or workspace on the platform page. Links that carry
  secrets (`#join=`, `#device=`, invites, `#link=`, a Doc's key) never move.
- A push for a chat message or a Cloud tab opens it on the platform page.
- The daemon's own copy of the page is about 80 KB smaller: it no longer
  carries the platform's views.

## Control

- The hub serves the platform page on its own host (`--platform-host`,
  `ARUGULA_PLATFORM_HOST`) under a strict CSP (no inline scripts, no
  `eval`, no frames), and answers only the platform's routes there.
  `/control.json` says where it is (`platform`).
- The platform lists the reader's projects (`GET /api/projects`).

## Also in this release

## For people who run their own control

Chat and Cloud workspaces need a platform host now: set
`ARUGULA_PLATFORM_HOST` to a name that points at control (a second host,
like `app.<your control's domain>`). Without one, control's page still
runs your machines, devices and teams, but has no chat or Cloud
workspaces. See docs/control-ops.md.
