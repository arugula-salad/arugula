# Arugula 0.69.20

`arugula cloud rebuild` now stops for commits on any branch no remote has, stashes, and changed or untracked files in every git repo on the machine, session users' too, and names them. Files and images in chat can be up to 100 MB each on Arugula cloud, and a team keeps up to 2 GB of them. arugula grants add --team gives a machine's agents threads.read or threads.post over a team's channels, and arugula grants lists the grant by the team's name.

## Added

- **Give a machine's agents a team's channels** (#2459). `arugula grants add geek threads.read --team Acme` names the team by its name
or id. A team's grant is for `threads.read` and `threads.post` only; the other
powers are over a project. It takes one scope: `--team`, `--project` or
`--dms`. A control from before team grants refuses one, and the CLI says so.

## Changed

- **Files in chat up to 100 MB** (#2457). Chat's files now live in Arugula cloud's object storage instead of its database
(Arugula #125). They're still read only through Arugula cloud, and only by the
people who can read the room. Files posted before move across on their own.

## Fixed

- **A cloud rebuild checks every branch and stash first** (#2456). Before, it looked only at the checked-out branch of the repos the workspace's setup
cloned, so other branches, stashes and other repos were lost with the old machine.
`--download FILE` saves every repo with work to a tarball; `--force` rebuilds anyway.
On a machine made before this release, the CLI looks itself, in a pane it opens
there and closes.
