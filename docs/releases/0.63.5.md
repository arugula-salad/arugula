# Arugula 0.63.5

Agent sessions pick their own cloud workspace, ask you with buttons you can press from the channel, and post their answers back in the thread.

## New

- **A session picks its own box** (#1565, native #214). In a project with several cloud workspaces and no "agents run on" setting, `@arugula` no longer asks which one to use.
  - It picks a workspace that has the repo you asked about, preferring one that's awake with a free session slot, then the least busy.
  - It asks only when it can't tell which repo you mean, or when no workspace has it.
  - The card says which box the session is on. Its **Move to…** menu sends a queued or done session to another box with the same repo, along with its conversation when the box can archive it.
  - An "agents run on" setting still wins.
- **Asks come to you as a form** (#1565, native #214). What a session needs from you shows on its card with a button per choice: which repo, or the agent's own question.
  - For a session started from a channel message, the ask also shows in the channel, so you can answer it there without opening the thread.
  - An open ask counts as a mention for whoever asked, and is pushed like one, until it's answered.
- **Each turn's answer is posted in its thread** (#1564, native #213). When a session's turn ends, the agent's last message goes in the thread under its card. A long one is cut at about 2,000 characters, with a link to the session for the rest. It's posted once per turn, wakes no one with its `@`s, and never prompts a session. A box needs 0.63.5's template to send it.

## Fixed

- **A session's first prompt leaves out the platform's questions and your answers to them** (#1564). Your reply naming a box or repo is no longer passed to the agent as part of the request.
- **A rebuilt box's prompt no longer says the conversation was lost when the old box kept it** (#1563).
