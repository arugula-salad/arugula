# Arugula 0.33.0

A day of fixes to the web client from a review of what's confusing in it:
one bar everywhere, one name and one state for each thing, what's
clickable looks clickable, and the data sorted into sections.

## One bar for every place

- **Panes, Swarm, Chat and Agents share one bar** (#742): the machine and
  the places on the left, what the place offers beside them (sessions and
  tabs, chat's search, Agents' Recipes and Team), then **Commands** and
  the account menu on the right. The swarm has it too, and Agents' second
  row and its × are gone.
- **An account menu, top right.** Teams, Devices and machines, Add a phone
  or browser, Sign-in and account, Plan and Sign out moved there from the
  machine menu; the first page (no machines yet) has the same menu.
  Permission rules, Developer settings, Notify this device, Getting
  started and the command palette moved there from the session menu, which
  now holds only what acts on the session, Close session last.
- **The command palette has a button**, *Commands*, with its shortcut, in
  every place's bar.

## One name and one state for each thing

- **A machine's state reads the same everywhere** (#746): the machine
  menu, Devices and machines, Teams and the phone's sheet all say
  *online*, *connecting* or *offline, seen 34m ago*, from control first.
- **The swarm's counts agree**: *machines* counts every machine the menu
  lists, *need you* counts what's on the rail (a finished card that left
  stops counting, in every view), and an unreachable machine isn't busy.
- **One name per browser.** Control notes which device each sign-in is,
  so Sign-in and Devices call it the same thing (*Safari on iPhone*), and
  Devices shows whether each browser is signed in, with Sign out beside
  Remove. Sign-ins from before say *An earlier sign-in*.
- Devices from before the rename read as the *Arugula app*; *Fountain
  runner online* no longer repeats the machine's name; Chat says
  *session* where it said *channel*; adding a machine to a team is one
  sentence and command, on Add a machine and in Teams.

## What's clickable looks it

- **Panes have a header** (#747) when a tab has more than one: what each is
  running, its project, the machine when it isn't the tab's, and which
  pane has the keyboard. Tab titles drop a program's status marks (✳, ‹,
  ❯, spinners).
- *Sized for another window* is a note and a button, **Use this window's
  size**.
- **Agents → Team** lists the team's agents as rows, each with *Run* and a
  copyable `delegate` call.
- **The swarm** shows how to move around as a tip under its bar (*Got it*;
  **?** brings it back), keeps more room between clusters, and keeps names
  off other clusters' panes.
- **Teams**: *Remove* and *Take out* read as destructive, the role pickers
  look like pickers, *Lock team…* says what locking does, and *Ask me
  first* sits by its checkbox.

## The data in sections

- **Teams** shows a team's **Members** and its **Machines** under their own
  headings (#748).
- **Devices and machines** says when each browser was last used, sorts by
  it, marks one that's signed out and unused for 30 days, and offers
  **Remove them…** for those. *Approved on* moved to the tooltip, and a
  machine's team shows once, in *In*.
- **Recipes** says which machine's they are, puts the projects with
  recipes first and the ones with none on a line each, and shortens paths
  under your home to `~`.
- **Agents → Team** lists every machine, and says why one lists none:
  *offline*, *didn't answer* or *offers none*. Before, a machine offering
  nothing was left out.
- **The swarm**: a card on someone else's machine says whose, its text is
  two lines at most with long paths shortened, and timeline rows go by
  the task their program names (Claude Code's) instead of `claude --resume`.

## First load

- **No *Add a machine* for an account that has machines** (#750, #749). A
  page whose machines arrived before its fonts were measured showed it
  until control's next refresh; and while machines connect, it says
  *Connecting to geek…*.
- **A link to a machine**: the address names the machine shown
  (`?machine=geek`), so a link or a reload opens it.
- **Chat's Activity starts with what needs you** on every machine: agents
  asking, failed commands and finished work, each with *Open* and
  *Dismiss*, counted in Activity's badge.

## For contributors

- **`just dev-control`** (#744) runs this checkout's web client as control
  serves it: a local control with a fake GitHub sign-in, machines joined
  to it through its relay, and the client rebuilt on every change. A
  headless device approves the joins and your browser, so the one click is
  *Sign in with GitHub*.

## Agent blocks

- **A busy agent block no longer floods the page** (#713). A page that
  already has a block's state now gets only what changed in each update:
  the fields, and the transcript entries from the first one that changed.
  Before, it got the whole transcript window, up to 400 entries, every
  time. Updates waiting for a slow page fold into one. The CLI and older
  pages still get whole states.
- **`wait --idle` waits for an agent that will carry on by itself** (#606).
  An agent can end its turn with background work still coming: subagents
  it held its turn for, a command it ran in the background, or a Monitor.
  `wait --idle` now keeps waiting while any of these runs, in the API, the
  CLI and MCP. The card still says idle; only the wait changes.
- A turn an agent runs when a background task wakes it counts as a turn of
  its own in `turns` and `recent_turns`, with its cost (#700). A cancel
  that ends a held turn now keeps what's queued and sends it next, instead
  of dropping it.

## MCP

- **Tools whose answer always has one shape list an `outputSchema`**
  (#580). These are `run`, `close`, `start_agent`, `agent_respond`,
  `read_file`, `read_forge`, `invite_person` and `device_call`, plus
  `read_thread` and `post_thread` with chat on. Answers are unchanged.

## Inside

Nothing changes for you here.

- Claude Code's proposed edits (the diff cards) are handled by the
  daemon's IDE module instead of the mux, so `arugula-mux` no longer names
  any integration (#699). Whether each edit should become a block of its
  own is #741.
- The web client names each operation it calls, from a table generated
  next to its types, instead of spelling the paths (#579).
