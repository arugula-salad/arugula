# Arugula 0.60.0

The rest of step 7's code (#1317): deploys. A project's owner approves a
deploy from a browser or phone with a passkey. A fresh hosted box applies
it with the environment's secrets, and the box is deleted afterwards. The
deploy log is hash-chained. Two drivers ship: chant→Fly and apps-platform.
Deploys, like runs, are off unless hosted workspaces are on for the account
(`ARUGULA_HOSTED_ACCOUNTS`).

## Deploys (step 7)

- **The approval** (M218, #1334). A deploy is planned first; the plan is
  what an owner signs. Only a project owner's browser or phone device can
  approve, with a passkey assertion the hub checks over the approval's
  bytes. An agent's grant, tool call or thread message never counts as an
  approval, and an approval is used once.
- **A fresh box per deploy** (M219, #1349). Each approved deploy gets its
  own hosted box, with no agents or panes. The box takes its one deploy,
  uploads the deploy's log, and is deleted, even on failure; a reaper
  catches any box left behind. Secrets reach the driver only through its
  standard input, limited to the names its driver allows, and never touch
  the box's disk or a pane.
- **chant→Fly** (M220, #1359). The driver checks out the commit, runs the
  repo's chant op, and approves its gates as the approver, relayed by
  Arugula. It then checks that the Fly app is healthy on one image and
  links chant's ledger entry. The Fly token must be scoped to one app and
  expire within 30 days. The GitHub token that pushes chant's ledger is
  minted for each run by the platform's GitHub App and writes only the
  deploy's repository, unless the environment holds one of its own. A roll
  back redeploys the image an earlier deploy ran. Environments keep their
  driver's settings (`fly_app`, `chant_dir`, …).
- **apps-platform** (M222, #1357). The driver pins an app's pointer in
  arugula-salad/planter-apps with a short-lived GitHub App token, then
  checks the app's health URL by revision. A roll back pins the earlier
  revision. Commits from forks are refused.
- **Arugula's own release** (M221, #1372). The `arugula-release` driver
  runs a green main commit's `scripts/release bump` on a deploy box and
  pushes the bump and tag with a token minted for that one push, then
  follows the release workflow. Only the project named by
  `ARUGULA_PLATFORM_RELEASE_PROJECT` can use it. There's no roll back: a
  bad release is fixed by a new patch release.
- **Minted tokens** (#1373). A deploy whose run mints a token that writes
  is refused when it's planned unless the GitHub App's installation grants
  Contents: write. A token for the deploy's own repository, read or write,
  needs that repository linked to the deploy's project, checked when it's
  planned and again when it's minted.
- **When things fail** (M223, #1360). A stuck lease is taken over, and a
  crash mid-dispatch fails the run or deploy instead of repeating it. A run
  a restart interrupted fails "interrupted by a restart; not run again".
  `arugula-platform stuck` lists what's held; the runbook is in
  docs/control-ops.md.

## Hosted workspaces
- **A hosted box's ports are private** (#1367). E2B served every port a process in a box listened on at `<port>-<id>.e2b.app` to anyone; boxes are now created with public traffic off, so dev servers are reached only through members' previews or a public preview on arugula.site. Boxes made by 0.59.0 should be rebuilt (`arugula cloud rebuild`).
- **The workspace template builds again** (#1366): the run user no longer asks for a fixed uid.
- **Windows** builds and tests of the hosted code are fixed (#1361, #1363, #1364, #1365).

## Fixes

- Deploys build on macOS again (#1368).
- **Opening a sleeping hosted workspace** from the CLI, MCP or the page no longer fails once while it wakes: control waits for the box's fresh connection instead of its old socket (#1370).
- The aru-097 guard and a terminal contrast spec pass again (#1371).
- After a restart, a run whose program kept going in its pane is followed to its end, not failed as interrupted, on slower machines too (#1374).

## Platform database
