# Arugula 0.68.3

A project's settings open with Access: every member sees the team's roles, whose machines and agent tokens hold powers there and what each does now, what an owner allowed, and the cloud workspaces. Deleting a Doc on your machine takes its copy on the platform down too, and a copy on the platform can be deleted there. loam, named by `--loam-url`, is the only sandbox provider for VM panes; `--wisp-url` and `--wisp-token-file` are gone. Your machines copy their Docs up to the platform only when you turn on Your Docs on the platform, under Teams; a team's machine doesn't copy them.

## Added

- **Prototypes start from the house look** (#2218). Every Doc prototype carries a small kit: `--ar-` colors that follow the Doc's light or dark, four text sizes, and `ar-btn`, `ar-chip`, `ar-header`, `ar-row`, `ar-dialog`, `ar-menu`, `ar-empty` and `ar-toolbar` classes. A prototype that uses none of them looks as it did, and agents are told the kit is there.
- **Plan a board in one call** (#2220). An agent can make a board with its groups and their tickets, new ones included, in one board_write call, and can name a board by its title.
- **Who can do what in a project** (#2164). Open a project's settings on the Projects page: Access is the first section. It lists the team's roles; whose machines can act in the project because they're joined to a member's account, and what that reaches; every power a member gave their machines' agents or an agent token over the project, with whose it is and a note when it does less than the power now; whether an owner allowed cloud workspaces and runs with every device asleep; and the project's cloud workspaces, where an editor has full use. Each part says whose word it is. Nothing on it changes anything: it's a view. The same view prints with `arugula grants ls --project NAME`.

## Changed

- **Projects opens the project you were in** (#2222). The rail's Projects used to open the list of projects. It now opens the project
last opened or picked in this browser. "All projects" in the picker still opens
the list. If that project is gone, or you can no longer see it, Projects opens
the list instead and forgets it. It's kept per browser, and signing out of the
page clears it.
- **A Doc's copy follows the Doc** (#2165). When a machine has copied a Doc up to your Docs on the platform, deleting the Doc on the machine now takes the copy down too, even with copying turned off, instead of leaving it there and making a second copy at the next change. Links to that copy, a board's included, then read as a deleted Doc. A copy can also be deleted on the platform by anyone who writes in its project, from the Doc's page; the machine's next change to the Doc brings a new copy, with a new link.
- **A deploy's box admits no links or guests** (#2215). A deploy's box admits none of its project's people, and now no session links or ssh guests either, including ones made before the box was told it's a deploy's. Nothing is deleted. The box refuses to make a new link or invite, and its Access view lists what it holds and says it admits no link or guest there.
- **Your Docs on the platform is a choice of yours** (#2158). A machine joined to your account alone copies its Docs to your Docs on the platform, where they read with the machine asleep, only once you turn **Your Docs on the platform** on, under Teams on your machines page. It's your account's own setting: a team can't turn it on, and it doesn't turn chat on. If your account had chat on for itself, it's on already. Off stops new and changed Docs from being copied; copies already there stay until you delete them.

A team's machine no longer copies its Docs: before, it copied every Doc on it into the personal Docs of the member who added it. The platform now refuses its copies whatever version it runs, and the Docs stay on the machine. Copies it made before stay where they are, and nothing removes them; you can delete one on the platform, and deleting the Doc on the machine takes its copy down.

A machine joined to your account alone also follows your teams' chat for the threads on its panes now, so their readers reach the platform.

## Removed

- **After the older machine model: what to do** (#2205). v0.68.0 removed synced history, the dial-out tunnel with its host tokens and
invites, and remote blocks, but didn't say what to do about them.

- **A host that dials out** (`arugulad --peer`, `--token`, `--join`) doesn't
  start on v0.68.0 or later: the daemon refuses the flags, and nothing can
  reach it from outside once it's gone. Move it to Arugula control first:
  `arugulad join` on that machine, then update it.
- **`arugula hosts token`, `arugula hosts revoke` and `arugula hosts invite`**
  are gone; `arugula hosts` is `add` and `rm`.
- **A `synced/` directory** in the daemon's state directory holds history
  other hosts synced there, sealed, and nothing reads it now; the daemon
  says so in its log at startup. `rm -r ~/.local/state/arugula/synced`
  removes it.
- **The Sprites adapter (wisp) is removed** (#2205). The daemon's Sprites adapter, which ran VM panes on a wispd on the machine or
on Fly's sprites, is removed with the older machine model. loam is the only
sandbox provider: `--loam-url` (or `LOAM_API_URL`) names it, with its key in
`--loam-key-file`, and without it VM panes are off. The `sandbox-providers`
flag gates it as before, on the running daemon.

- `--wisp-url` and `--wisp-token-file` (and `ARUGULA_WISP_URL`,
  `ARUGULA_WISP_TOKEN_FILE`) are gone: a service file or script that still
  passes them won't start, so take them out before updating.
- A wisp token left on disk (`~/.local/share/wisp/token`) is never read; the
  daemon says so in its log at startup, and leaves the file alone.
- A layout saved with a machine from wisp loads whole: the daemon logs one
  line per such machine and keeps it with its pane, which says its machine
  is gone (or that VM panes aren't set up) until it's used again.
