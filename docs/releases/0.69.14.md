# Arugula 0.69.14

An agent session started on an issue now moves that issue's board rows to Doing while it works, and each row shows the session, its state and a link to its thread. On a board, Close epic is a quiet button beside Lanes and Steps, and Done and a new Links toggle sit above the Steps chart. Links shows every arrow until you hover a row. Docs lists sort by Updated or Created, and an open Doc says when it was created and last edited. When a merged PR moves a Plane ticket to Done, Arugula now comments on the ticket naming the PR, never re-closes one a person reopened, and each connection has a Close on merge switch. An agent's wait can watch several pull requests until checks finish or fail, they're ready to merge, or someone merges or closes one, with each one's failing checks and merge queue state.

## Added

- **Docs sort by created or updated** (#2377). Both Docs lists (a machine's and the platform's) have a sort beside the search, Updated
(the default) or Created, newest first, remembered in this browser. Each row's time follows
it: "edited 3h ago" or "created 2d ago". Under an open Doc's title, in the pane, the list's
preview, the Doc's page and a share link, a line reads "Created 4 Nov · edited 3h ago", with
the full date and time on hover. A Doc from before Docs were kept says only when it was edited.
- **Agents wait on pull requests** (#2379). `wait` takes `pr` (`OWNER/REPO#N`, a link or a PR block, one or several) and `until`: `checks_done`, `checks_failed`, `ready`, `merged` or `closed`. It returns when any of them gets there, with a verdict for each: its checks by state, the names of the failing ones, whether it can merge, whether it's in the branch's merge queue, and who merged it. It asks GitHub itself with your own `gh` login every few seconds, so a green PR's `mergeable` is never as old as the mirror's last read, and a pull request you can't see answers as one that doesn't exist.

## Changed

- **A board row shows its agent session** (#2374). A session started on an issue (`session_start` with `issue`, or @arugula on the issue) counts as work under way on every row of that issue, on every board of the project. It is Doing while the session is queued, working or waiting on its person, and while a finished one's PR hasn't been sent; failed and stopped sessions don't count. An open PR still puts the row in Review, a closed issue is Done, and a live session keeps the row from being marked stalled. The row's card and drawer show the session as a chip, and `board_read` names it under the row.
- **Board chart controls moved** (#2375). Close epic moves to the right end of the Lanes/Steps row and turns red only on hover or focus. In Steps, Done and Links sit in a small row above the chart, with an icon and a label (icon only on a phone). Links is on by default and remembered in this browser: on, every arrow shows and hovering or tapping a row shows only its own; off, arrows show only for the row you hold.
- **Agents see the epics-as-boards setting** (#2372). `capabilities` lists `epics_as_boards` (on or off) for each Plane connection with a line on what it does, and `board_write`'s description says where it is switched on.
- **Close on merge says so, and has a switch** (#2372). The comment follows the connection's footer setting. The switch is on by default,
is in the project's Plane settings, and shows in `capabilities` as `close_on_merge`.

## Fixed

- **Plane relations reach the board** (#2366). Plane doesn't change a work item's update time when a relation is added, so the
board only learned of one at a full backfill. A Plane webhook for an item now reads
its relations with it, and each reconcile reads the relations of a slice of the
project's open items, so a relation made or dropped in Plane reaches the board.
- **An agent's ALL-2547 finds its Plane project** (#2372). `forge_read`, `link`, `tracker_write` and `board_write` (making a board with
a plan) take an `IDENT-N` such as `ALL-2547` with no `project`. When the
default project (the one the agent was started on, its clone's linked
project, or the personal one) has no Plane connection with that identifier,
they look among the projects the machine's grants reach: one match is used,
several are named so the agent can pass `project`, and none says which
project it looked in and lists the identifiers it could have used.
