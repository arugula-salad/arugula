# Arugula 0.60.9

Made as a deploy, like every release since 0.60.6.

## New

- **A project's deploy history** (#1426). Each environment on a project's
  Environments settings page lists its latest deploys, with their state,
  commit and when they last moved, each linking to its page; **Older**
  loads more. `arugula deploys ls [--env NAME]` lists them from a
  terminal, and `GET /api/projects/{project}/deploys` serves both. Before
  this, a deploy that was done was reachable only from its push or a
  link.

## Platform step 8, off until configured

These ship dormant: each waits for its configuration or an import run by
hand.

- **Account links by GitHub id** (#1410, M229). Nothing links until the
  issuer key is set and a product is registered on the hub with a link
  secret (`arugula-control issuer add-client`, `issuer link-secret`). The
  hub asks for consent the first time a product signs someone in.
  Settings gains a **Linked products** section.
- **The Claude credential broker moves to the platform** (#1406, M231).
  The platform's key isn't used without `ARUGULA_INFERENCE_ANTHROPIC_KEY`,
  and studio can't reach it without `ARUGULA_INFERENCE_CLIENTS`. A project
  member with the project's own key can already use it. Settings gains
  **Claude spend**.
- **hud and studio become clients** of the hub's issuer (#1413 M237,
  #1415 M236): off without the issuer key (0.60.7) and their client rows
  on the hub. Owners can now set and clear project secrets on a project's
  settings page, and grant one to a product by name. Studio's and hud's
  own changes are in their repos (studio#451, hud#925).
- **Planter's accounts and repos** (#1414, M232): an ops import, run by
  hand (`arugula-control import planter`, `arugula-platform import
  planter`). Nothing runs on its own.
- **The planter driver** (#1417, M233): off without `PLANTER_PROJECTS`
  and planter's App (`PLANTER_APP_ID`, `PLANTER_APP_PRIVATE_KEY`).
- **redone is absorbed** (#1418, M235): an ops import, run by hand
  (`arugula-platform import redone`). Its MCP shim answers only tokens
  that import carries over. The Infisical projection is off unless
  `ARUGULA_INFISICAL_PROJECTION` is set.

They add platform migrations 0032–0037, all additive.

## Fixes

- **CI's Linux tests build with four jobs** (#1428). Six ran the runner
  out of memory, which looked like a lost runner.
- **The planter renderer works under a symlinked run directory** (#1427),
  as on macOS.
