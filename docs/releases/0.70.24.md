# Arugula 0.70.24

Arugula cloud now decides who reaches your machines, so it can read the terminal traffic it relays (it's built to keep none of it); the pages and docs say so. Build opens on one list of your panes from every machine, a section per machine, with the machine as a filter. A pane still opens on its machine's page. A card's sessions show on its board row and in its drawer, Build's list of panes has an Agents only filter, and Runs and Workspaces are under Build › Machines. The Sessions page is gone.

## Changed

- **Arugula cloud can read what it relays** (#2599). Arugula cloud used to promise that it relayed your terminals without being able to read them. Since machines take Arugula cloud's machine tokens (aru-141), that's no longer true, and the sign-in page, Getting started, the join and approval screens, the connection tooltips, the README and the docs now say what is.

Arugula cloud can read the terminal traffic it relays, and it can let anyone, itself included, open a shell on any machine your account reaches. So can whoever breaks into it or steals a signed-in session. It's built to keep none of the terminal bytes it relays.

What limits it: a machine token is for one machine and one role, lasts five minutes and opens one channel; a viewer's can't type. Each machine logs every remote session in `remote-sessions.jsonl` in its state directory. And `arugulad sharing remote-input off`, run on the machine, makes everyone who comes through Arugula cloud a viewer. Passkeys still approve deploys, standing run grants and owner changes, and an agent never does. A daemon's own page on your tailnet, and `arugula attach`, don't go through Arugula cloud at all. The whole of it is in `docs/control-e2e.md`, "What control can do to your machines".
- **Build opens on every machine's panes** (#2598). Build no longer opens on one machine's page with its picker in front. Its Panes is a list of every pane on every machine you reach, grouped by machine, with what needs you first and the pane you had open last marked. *Every machine* above the list narrows it to one. A row opens the pane on its machine's page, and Panes in that page's bar comes back to the list. Swarm's Back goes there too.
- **Sessions folds into Boards and Build** (#2601). The Sessions page leaves Plan's bar and the phone. Its pieces live where the work is:

- **On the board.** Each card's sessions show on its row in Lanes, and in its drawer in Lanes or Steps: a computer's session put on the card, an agent that isn't attached to the row, a cloud workspace's session. Each shows its state, and what waits on you comes first. Finished sessions are left out. Click a computer's session to open its pane in Build.
- **In Build.** **Agents only**, beside the machine filter on Build's list of every machine's panes, shows only the panes with an agent in them. The two filters work together.
- **Under Build › Machines.** **Runs** and **Workspaces** are buttons at the top of the Machines list. A run's unread count is on Build now.

Putting a session on a card, or moving it to another card, is in the session's ⋯ menu. An old link to `/p/<project>/sessions` opens the project's Boards. A session's own page, `/p/<project>/sessions/ses_…`, stays where it was. The Label, Tracker, Asked by and Going only filters are gone with the page.
- **One switch everywhere** (#2604). The switch's look moved out of the Settings pages into its own file, web/src/shared/switch.css, so every `.sw-switch` gets it. The dialogs' on/off choices that take effect at once now use it.

## Fixed

- **A page that fails says so** (#2597). A page that hits an error while drawing now shows a short note with Try again, instead of freezing on its last frame; the rail and other pages keep working.
- **A machine refuses a token from before it started** (#2602). A machine remembers the tokens it has taken only while it runs. It now also
refuses any token issued before it started, so one taken before a restart
isn't taken again after it. The page and `arugula` ask control for a new token
when a machine refuses one, so right after a restart that costs a second or
two at most.
