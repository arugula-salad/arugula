# Arugula 0.59.0

Step 5 of the platform roadmap (#1235): a Cloud workspace becomes a real
machine, `arugulad` in an E2B sandbox attached to a project, with
terminals, agent blocks and previews through the daemon. It pauses only
between turns and wakes when someone opens it. Hosted workspaces are off
until control names accounts in `ARUGULA_HOSTED_ACCOUNTS` and has an E2B
key; this release ships the code and the first workspace template.

Also in this release, the first part of step 7 (#1317): runs on hosted
workspaces, with schedules, event rules, a standing grant and run logs,
and per-project keys for every stored secret.

## Notices

- **Pokes for older daemons end on 2026-11-21.** Daemons older than 0.57
  stop getting pokes for linked repos after 2026-11-21; their PR and issue
  blocks keep polling GitHub with their own login. Update with
  `arugulad update` (M174, #1220).
- **Hosted VMs (M20) are gone.** The old "New hosted VM" product, already
  off, is removed with its routes and table (M190, #1352). Labs VM panes
  are unchanged.

## Hosted workspaces (step 5)

- **A hosted machine is `arugulad` in a rented sandbox** (M178–M180, #1308,
  #1306, #1305). An owner's device signs a project delegation once; control
  then enrolls each new box into that project with a one-time enrollment,
  failing closed. Clients trust such a machine only for its project and
  show it as "Hosted: the operator can read". A project's editors have full
  use of it; viewers watch.
- **`arugula cloud`** (M179, M183): `create`, `ls`, `open`, `edit`,
  `rebuild`, `delete`, `secret`, `key` and `preview`. Setup runs in a pane
  anyone on the project can watch; a spec edit shows "rebuild needed", and
  a rebuild warns about uncommitted and unpushed work and offers a download
  first (#1330).
- **Pauses only between turns** (M181, #1323). While the daemon reports
  busy the box is held; when it's idle it pauses with memory and disk kept.
  **Wakes on open** (M182, #1326): from a terminal, a block, the phone, the
  CLI or MCP, with "waking…" on the page.
- **Agents on hosted workspaces** (M184, #1335): "+ Agent" opens an agent
  block on the box; agents on your machines reach it through MCP and
  `cloud.drive` grants; closed agents' transcripts are archived read-only
  under the project.
- **Whose key pays** (M185, #1315, #1342). Inference keys never enter a
  box: E2B's egress proxy sets them on requests to the provider. A
  project's own Anthropic or OpenAI key (`arugula cloud key set`) pays for
  its agents; allowlisted accounts run on the platform's spend-limited key
  under per-account caps.
- **Previews** (M186, #1325; M187, #1344). A dev server's port opens in a
  members-only browser block. A port an owner or editor marks public gets
  `<id>.arugula.site` for 7 days unless renewed; control serves public
  pages, so it sees them, and strangers never wake a box. Abuse:
  abuse@arugula.io.
- **Metering** (M188, #1311): active seconds per workspace and project,
  reconciled with E2B; `arugula-platform usage` gives cost per active hour.
- **Moving off Managoat** (M189, #1353): each beta Cloud workspace can be
  moved to a hosted one, with its secrets and transcripts. The deletion
  notice comes separately.
- The workspace template (`arugula-workspace:v0.59.0`) is built on E2B by
  this release (M177, #1304). Boxes are created secure, and a box whose
  in-box API isn't locked is refused (#1339). A box never forgets a device
  removal it has seen (#1331).

## Runs and deploys (step 7, so far)

- **Runs** (M208, #1320; M210, #1321; M211, #1328; M212, #1336, #1347;
  M213, #1346; M214, #1333; M215, #1348; M216, #1345): a project's runs
  on its hosted workspaces. Run specs, cron schedules, GitHub event rules
  (forks and outsiders refused by default), a standing grant an owner
  signs, `arugula runs …`, MCP `start_run`, `read_run` and `wait`, and
  runs on the platform page. Run logs and artifacts upload to the
  platform's bucket. All of it is off unless hosted workspaces are on for
  the account (`ARUGULA_HOSTED_ACCOUNTS`).
- **Deploys** (M217, #1322): environments, deploys and a hash-chained
  deploy log, as tables only. Approvals and drivers come later.
- **Per-project envelope keys** (M209, #1324). On its first start after
  this deploy the platform re-seals every stored secret (Cloud secrets,
  hosted workspace secrets, inference keys) under per-project keys, row by
  row and idempotently. **A rollback past 0.59 can't open re-sealed rows
  until it's rolled forward again.** Rotating the master key is now two
  steps: `ARUGULA_CLOUD_SECRET_KEY_NEXT`, then `_PREVIOUS`
  (docs/control-ops.md).
