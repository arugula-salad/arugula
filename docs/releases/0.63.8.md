# Arugula 0.63.8

You can reset your own devices when nothing can approve a new one, control can email you security notices, the desktop app opens chat in a window of its own, and What's new tells you what changed.

## New

- **Setup installs the hooks** (#1591, #239). *Use Claude Code with Arugula* and `arugula setup claude` also run `arugula hooks install`, and say which settings file changed.
  - Getting started's Agents step gets a **Questions on cards** check.
  - A terminal Claude that needs you but has never reported through a hook gets a chip on its pane, with **Set up**.
- **Hints** (#1591, #241). Arugula shows a short hint from something it noticed, once per account: the first one is `:5173 is listening` · **Open beside** on a pane whose dev server just started. Only one shows at a time, never while you type. Turn them off with **Tips** under This device in Settings.
- **`arugula --help` in groups** (#1591, #248). Commands are listed under Panes, Blocks, Agents, Sharing, Machines and control, Cloud and projects, and Setup. What hooks and clients run (`ask`, `hook`, `inbox`, `bridge`, `attention`) moved to `arugula help plumbing`.
- **Docs look like Arugula** (#1593, #253). A Doc has its own paper, ink and leaf in light and dark, whatever the app's theme, with display headings, a reading measure, quieter tables and warm code. A shared Doc follows the reader's light or dark setting. Chat's Markdown is unchanged.
- **Reset your own devices** (#1617, #1582, aru-119). When no device can approve and you have no recovery code, *Approve this browser* offers a reset: a fresh GitHub sign-in, then a 48-hour wait, then that browser becomes your first device with new recovery codes. Your other devices and your email are told when it starts, and any device can cancel it. Support has the same reset as `arugula-control account-reset` (#1608).
- **An email for security notices** (#1616, #1609). *Sign-in and account* shows the address control keeps: GitHub's primary verified one, or one you type and verify by a link. Only notices go there, such as a reset of your devices. A control sends email only when it's given an SMTP server.
- **Chat in its own window in the desktop app** (#1605, #1596). Opening chat no longer replaces your terminals; it opens one chat window and reuses it.
- **What's new** (#1621). After an update, a small panel lists the release's headlines that apply to you, once, with Try it. The account menu opens it again.
- **Empty views do the next step** (#1621). + Pane offers a pull request, an issue, a web page and a Claude Code conversation; Getting started ends with Things to try; empty sections on a project's home, Runs, Docs and the bell offer the step that fills them. The platform can create a cloud workspace from a dialog, and lists every environment's deploys.
- **Docs: callouts, stat tiles and named colours** (#1614, #254; #1618, #256). GitHub's `> [!NOTE]`-style alerts draw as callouts, a ```` ```stats ```` fence draws a row of tiles, and drawings and charts take named colours (leaf, pepper, sky, plum, sun, stone, ink, paper) that follow light and dark.

## Fixed

- **Link GitHub in the desktop app** (#1587, #235). *Sign-in and account → Link GitHub* used to sign the window out. Now it opens your browser to finish, like installing the GitHub App, and the window says when it's linked. Control refuses a link started from the desktop app's window, the same rule as adding a passkey.
- **The desktop app's account actions** (#1592, #251). Add or remove a passkey, link or unlink GitHub, sign out everywhere and delete your account: in the desktop app, each opens your browser up front and the window waits with *Check again*, instead of failing after you click. In a browser they work as before.
- **Approve this browser says why** (#1606, #1581). Asked again on a browser you approved before, it says approvals stay with the address they were made on, and offers your recovery code or a reset. Control's runbook for moving address now carries approvals over before the old one goes dark.
- **The desktop app says when it isn't signed in** (#1603, #1580). After control moved, the window wasn't signed in to the new one and gave no way to chat. It now says so, with *Sign the app in*.
- **A session card's Open says where it goes** (#1604, #1595): *Open on Control ↗*.
- **Threads whose only replies are the platform's** (#1615), such as a session's card, now list in Threads, so their unread can be read or unfollowed.

### Labs: boards

- **Rows from a newer build** (#1588). A row pointing at something this build doesn't know shows as a plain note, and editing its text keeps what it points at. This lets control roll back a release without breaking boards.

## Note

- Control gains a table, `account_prefs`, for hints seen per account (`GET`/`POST /api/me/prefs`). It's additive.
- Control's 5-minute log adds webhook-to-row times counted per UTC day, so the M173 gate reads a day's p95 across deploys (#1594, `docs/control-ops.md`).
- Control gains tables for email and resets: `account_emails`, `email_tokens`, `email_sends`, `reset_requests` and `account_resets`. All additive, so an older control still opens the database.
- Control's GitHub sign-in now asks for `user:email`, to read your verified address. Email needs `ARUGULA_CONTROL_SMTP_URL` and `ARUGULA_CONTROL_MAIL_FROM` (both or neither; `docs/control-ops.md`). Without them nothing is sent and the page says so.
- `just sweep` deletes the old builds cargo leaves in target directories (#1619), and the daemon compiles about a quarter fewer generic copies (#1620).
