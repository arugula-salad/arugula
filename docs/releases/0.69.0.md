# Arugula 0.69.0

Boards show the order work goes in. A Steps view beside the lanes lays out each phase's open work by step, with the agents on it live and each row's links drawn on hover, and agents say what comes before what with the new `link` tool. `board_write` no longer has `relate` and `unrelate`: an agent prompt that uses them needs `link` instead. Also: Docs on the rail, CI alerts as native issues, and chant-fly deploys that approve chant's own plan, which needs chant 0.124.64 or newer and your passkeys in .chant/trust.json.

## Added

- **Steps on a board** (#2272). Every read of a board works out each row's step from its open `blocks` and `before` links
and stacked PRs: 1 plus the highest step of the open rows before it. Nothing is
stored. `board_read` prints a `Steps` block after the lanes, each step's rows in
the order of what they unblock, and `Chain:` with the longest open chain; the
JSON carries `step` on each row. Doing and Review rows are step 1. A blocker on
another board counts as one step, and the row's blocked-by mark names that
board and its lead. Rows in a loop of blockers (Plane can make one) share a
step and are marked `in a cycle`.
- **A Steps view on boards** (#2275). Switch a board between Lanes and Steps in its header; Steps is the default
on a phone. Each of the board's groups is a phase, with its steps as columns
(sections on a phone). Done rows are counted in the phase's header and not
drawn, and step 1 folds after eight rows behind "+M more". A row with a
running agent shows its state live on its bar.

Hovering a row (tapping it, on a phone) draws arrows for its links, each kind
its own way: a thin arrow for `before`, a heavier warm one for `blocks`, a
dotted line for `relates`, a double line for `duplicate_of` and a dashed arrow
for `discovered_from`. The drawer lists the same links in words.

Drag a row up or down inside its step to reorder it (↑ and ↓ in the drawer on
a phone). Only the row's place in its group changes; the step is still worked
out from the links. A reorder made on an order someone else has since changed
isn't made: the row says it was moved first by someone else.
- **CI alerts as native issues** (#2277). A project's settings have a CI alerts section. Turning it on shows the URL
chant's tick posts to and a key, shown once, that signs its events; Rotate
key makes a new one, and Turn off removes it.

In the repository, `ci.green.notify` in `chant.workspace.json` names the
two environment variables (`webhook` and `key`), and each is a repository
secret of that name. Then a red branch opens one issue, written by chant CI
rather than by a person or an agent. Red again, the bisect's culprit (with
its author and pull request when the repo is linked here) and a branch still
red after `staleAfter` hours comment on it, and the next green commit
comments and closes it as completed. A red after that opens a new issue.

The people the section names are mentioned on a new red issue, and assigned
it if you choose, and mentioned again on the culprit, the stale reminder and
the green. Their push settings apply.

## Changed

- **Panels, side sheets and the phone's Close pane ask like the rest** (#2268). The big tip over a pane, the full-size picture, Add a pane and the Needs you drawer now share the dialogs' behaviour: one dim backdrop, Escape closes only the one on top, focus stays inside and goes back to what opened it, and buttons sit at the bottom right with Cancel first. On a phone, Close pane in the sheet now asks before it closes, as Close tab does, and says when a process is running in it. Docs' delete asks in a dialog too.
- **Agents say what comes before what** (#2263). `link` adds and removes up to 50 links in one call, between a project's
issues and PRs, with no board needed. Each link lands on its own and the
answer says what became of every one: added, already there, removed, not
there, or refused and why. An item is `#N`, `owner/repo#N`, `IDENT-N` or an
`iss_`/`fi_` id. The default kind, `before`, says the first item comes first;
it shows on both items' rows in a board, like the other kinds, and doesn't
keep a row out of the Ready line (only `blocks` does). An agent takes off only
the links its own machine made. Needs the machine's `issues.write` grant over
the project.

`board_write` no longer has `relate` and `unrelate`: use `link` with kind
`blocks`, `relates`, `duplicate_of` or `discovered_from`.
- **Docs on the rail** (#2269). Docs is a place on the rail of both pages, after Chat, wherever control has a platform page. It opens `/docs`, which shows Team Docs first; Mine is one click away and remembers your choice in this browser. A Doc that is a copy from a machine says which one. A machine on its own keeps its Docs page as it is.
- **Pickers and dialogs behave alike** (#2274). The dialog to start an agent, the directory, conversation and Studio app pickers, the palette and the chat room switcher all open on the same dialog as the rest of Arugula. The channel dialogs gain a title.
- **Approve the plan chant made** (#2071). Asking for a chant-fly deploy's approval now starts a plan run on a box of its
own, with no Fly token. The commit is fetched with a GitHub token that only
reads, chant runs the op to its gate with no token at all and records its
plan, and only once nothing the op ran is left does Arugula check what chant
added to its ledger and push it itself, with a token the repository's code
never sees. Owners are asked once the plan is there,
and the approval page shows chant's gate and plan digest. Your passkey signs
chant's own gate statement for that plan, and on the apply box chant checks the
signature itself against `.chant/trust.json`, after checking the plan isn't
stale.

What a repo needs before Arugula can deploy it this way:

- `@intentius/chant` 0.124.64 or newer in its `package.json`. The driver
  refuses an older chant and says which version the repo pins.
- Each approver's passkeys in `.chant/trust.json`, as `arugula:<account>`.
  `arugula chant trust-entry` prints the entries to paste in. Keep a signers
  file there too, even an empty one.

A chant-fly deploy asked for before this has no chant gate: plan it again. An
environment that held its own `GITHUB_TOKEN` and has no GitHub App installed
can't plan a chant-fly deploy, since the plan run's token is always minted.
Roll backs and the other drivers are approved as before.
- **Every colour comes from the palette** (#2281). A check now fails the build on a raw colour in a stylesheet (`web/scripts/check-colour.mjs`): shadows, tints and borders are the palette's tokens, so they follow the scheme you picked.
