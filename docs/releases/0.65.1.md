## New

### nvim in Arugula

For everyone; there's no Labs flag.

- **A pane running nvim is an editor** (#1752, #1730). The daemon finds the nvim in a pane (0.10 or later) and reads it over nvim's own RPC socket, with nothing installed. The pane shows `file:line (nvim)`, can be followed, and raises the same "errors after a save" and "merge conflict" reasons it does for VS Code. With arugula.nvim installed the plugin attaches to the pane instead, and it's still one entry in the swarm.
- **Add arugula.nvim in one click** (#1754, #1733). When nvim runs in a pane without the plugin, the pane offers to add it. It's written into nvim's own package directory and loaded into the running nvim, with no restart and no config file touched. If a plugin manager already owns a copy, nothing is offered and an install is refused.
- **An Editor preference** (#1755, #1731): **VS Code**, **nvim** or **Ask each time**, in Settings. Open in editor follows it from the pane menu, the palette, the swarm, the diff and file blocks, and a new *Open in editor* link on Claude Code's diff cards. nvim opens the file at its line in the pane's nvim, or in a new nvim beside it. Until you choose, it's VS Code. Once one of your panes has run nvim, the first Open in editor asks, with *Remember this* ticked.
- **Claude Code's proposed edits as a vimdiff** (#1753, #1732). Each one opens as a tab in the session's nvim, and `<leader>aa` / `:ArugulaAccept` or `<leader>ar` / `:ArugulaReject` answers it. Answering in nvim, on the card or in Claude Code's terminal settles the edit in all three. The card says "Also open in nvim" while nvim shows it.
- **An nvim editor block** (#1757, #1734). New editor block offers VS Code or nvim, by the Editor preference. An nvim block runs your nvim with your config, arugula.nvim in it, and the page's colors, and comes back after a restart.
- **nvim tips** (#1749, #1756, #1735). A key tip on each nvim start, from 58 tips each checked against nvim's `:help` in CI, whose button opens that help in the pane. Chips offer arugula.nvim, nvim for Open in editor, and Claude's edits in nvim. A help card, "nvim in Arugula", comes up on the first nvim pane of a tab.
- **Big tips** (#1751, #1737): a new place for a tip, covering one pane until it's answered, with "Don't show tips like this again". Settings › Tips has a **Big tips** switch. A phone draws none.

### Boards

Boards stay behind the `boards` Labs flag (decision aru-122); with it off, nothing here changes and every board route is a 404.

- **Issues on boards** (#1712, #1709, #1714, native #289–#291). A row's *points at* field searches the project's issues, PRs and runs as you type. **New issue…** in a zone makes a native issue and puts a row on it there. A row on an issue or PR reads as a card: title, source link, state and assignees. `GET /api/projects/{project}/work` is the search behind it.
- **Triage** (#1715, native #292). With boards on, the bar's Issues becomes **Triage** and lists the project's open issues, native and GitHub, that are on no board; **Add to board…** puts one on a board in a zone. Boards come first on the project home.
- **Epics** (#1743, #1758, native #301, #302). A board can be renamed, given a goal, and shows "3 of 5 issues done", counted from its rows on issues (a PR, run or link doesn't count, and an issue you can't read counts toward neither number). **Close epic…** asks "What can a person now do?"; a closed board shows **Done** with its date and note, folds under *Done (N)* on the Boards page and project home, and can be reopened. Its rows stay editable. Owners and editors can do this; viewers see it without the buttons. `board_read` gives agents the goal, progress and done note.
- The agent instructions and the plugin's skill now point at boards, and `docs/labs.md` says how to run a project on one (#1759).
- **Agents make and run boards** (#1796, native #335, decision aru-123). With the Boards grant set to read and write, an agent can make a board with a goal and zones, rename and move zones, close the epic with its done note and reopen it, and repoint a row it added. It still can't delete or repoint another hand's row, or delete a zone holding one, and a viewer's machine makes nothing. A board an agent made or closed says so ("Made by …'s agent on <machine>"). Agents are now told to run work of more than one ticket on a board.

## Changed

- **The daemon split, steps 19–24** (#232: #1720, #1740, #1742, #1744, #1745, #1746). New crates: `arugulad-agent` (the agent block), `arugulad-mcp` (MCP's server, the tool table and its results) and `arugulad-work` (the runs engine, behind a `Work` trait). Nothing changes for people.
- **Chat's rooms and sidebar are drawn together** (#1726, native #296). On load the rooms no longer appear under Channels and then jump into Starred a moment later.
- **CI** (#1739, #1741, #1747, #1750): its Docker Hub images come from a mirror at `ghcr.io/arugula-salad/ci`, so Docker Hub's pull limit no longer fails a run (`ARUGULA_IMAGES=docker.io` goes back to Docker Hub); e2e runs on twelve shards, from fresh times (native #259); and nvim 0.11.6 comes from its release, not Ubuntu's 0.9.
- **Logging** (#1729, M173): a webhook delivery that lands over 30 s after GitHub's time is logged with its event, action, delivery id and repo, by id only and never titles.
- **Contracts, checked** (native #219: #1760, #1761, #1765; native #220: #1762, #1764). control-wire's types have a JSON Schema, checked in and checked by CI, with example payloads that round-trip byte for byte; the internal port's types moved into `control-wire::internal`. Example files for cert, team, deploy and the drivers run from Rust, every case from its file alone, and e2e has example files for run and hosted (#1766). Nothing changes for people.
- **The platform split** (native #314: #1763, #1768, #1771, #1778, #1780, #1784, #1788). The hub and the platform get thin binaries, and the feature registry, agents, deploys, and chat and sessions move into their own crates (`arugula-platform-agents`, `-deploys`, `-chat`); the hub builds against `arugula-platform-api`. Nothing changes for people.
- **For contributors:** the nvim code builds and tests on Windows again (#1782). Flaky tests fixed (#1723, #1724, #1725, #1728; native #295, #297, #300, Arugula #280, #281, #283, #284).

- **Deploy approvals say what's deployed** (#1794, native #333). The push, the inbox card, the chat preview and Control's approval show the commit's subject and, for a release, the version it makes, with who asked and how long it has waited.

## Fixed

- **A PR block leads with its title** (#1770, native #317). The bar and tab read `#N title`; news that something finished (merged, checks green, closed) no longer sits under "Waiting on you"; and an ask or draft card sits above the block's actions instead of covering them.
- **The phone shows the port it opens** (#1727, native #299). A port opened from the sheet, palette, Getting started or a hint's *Open beside* is now the pane shown, rather than a terminal and port split at half width each.
- **Getting started notices a join as soon as it's approved** (#1724). For a moment after approval the daemon said "no code, not joined", and the dialog stopped looking.
- **The desktop app** no longer opens a second window if the hotkey is pressed before its setup finishes, and the hotkey hides the window reliably (#1723, native #295).

## Note

- No migrations on the daemon. The platform gains **0067_board_epics** (`goal`, `done_note`, `closed_at`, `closed_by` on a board; additive, sqlite and postgres) and runs it whether or not the flag is on. An older control reads a board as open. It also gains **0068_deploy_facts** (nullable columns on deploys) and **0069_board_agents** (`created_by_agent`, `closed_by_agent` on a board), both additive.
- nvim 0.10 or later is needed for the pane to be read without the plugin; the `]q`, `grn`, `grr`, `gra` and `]<Space>` tips need 0.11 and wait for it.
