## Fixed

- **Boards and issues in a pane show in the app** (#2562). Inside the app, the shell's blocks didn't know who was signed in, so a
Board block said "A board is on Arugula cloud… Open this machine in Arugula
cloud, signed in, to see it here" although you were. They now read as the
person signed in to the app, through the app's own address. A pane's
dashed *Put on a card* chip shows only where someone is signed in to put
it on one.

Links from a machine's pane to Arugula cloud's own pages (a board row's
issue, the card chip's card, a native issue's page, What's new's *Try it*)
now go to that page in the app, in place, so Back returns to the pane,
instead of opening another tab. On control's page they open as before.
- **Machines open again when some are offline** (#2563). A page asked Arugula cloud for a new machine token every time it retried a machine, every few seconds, including machines that were offline. With a few offline machines and a few tabs open, that used up the account's 3,000 tokens an hour, and then no machine would open. Now a page:

- keeps a token it never got to send and uses it for the next try to that machine, until 30 seconds before it expires
- asks for one token per machine at a time
- when Arugula cloud says it's limiting connections, stops asking for every machine on the page, for as long as Arugula cloud says (or at least a minute, then longer), and shows "Arugula cloud is limiting connections; trying again in N s"
- when a machine's token is refused, waits a minute or more before asking for that machine again
