# Arugula 0.69.10

A pull request closes an Arugula issue only through "Closes #N", "Arugula #N" or a title's "(#N)"; other mentions just link. The issue and its board row say which PR closed it, and how. Agent sessions run under the project's standing grant. Until an owner allows runs (Control, Devices and machines, Runs on cloud workspaces), asking Arugula in a thread starts nothing and says how. The Share dialog lists a session's read-only links with Revoke, and a link's page waits for a click before it connects. Sharing a Doc written on the platform with a team again says it's already there, and its pictures come with it.

## Added

- **End a read-only link sooner** (#2190). Revoking a link ends whoever is watching through it at once, and it won't open again. So does closing its session. `arugula links` lists them and `arugula links revoke ID` ends one.

A link's page now says what it is and connects only when you click. A machine older than this release can't list or end its links from the dialog until it's updated; they still end on time.

## Changed

- **Deploy approvals from before 0.66.6 must be given again** (#2091). Since 0.66.6 a deploy approval is a passkey assertion alone (DK4). The older
form, which also carried a device's signature, stopped being made then, and
each one lived at most 7 days, so none is still in date. A deploy that still
waits on one is canceled when its apply is tried, saying the approval is
from before passkey-only approvals and to approve it again. A box refuses
one the same way. The old approvals still read and verify on the deploy's
page, for history.
- **Agent sessions need Allow runs** (#2193). Agent sessions now run under the same standing grant as the project's runs.
Until a project owner allows them, asking Arugula in a thread, Agent on this, Try 3 and
`@codex review` start nothing, and the thread says how to allow them.

**To allow them**, a project owner opens Control's page and goes to *Devices
and machines*, then *Runs on cloud workspaces*, and clicks *Allow runs* next to
the project. It's confirmed with one of the owner's passkeys, on a computer or
a phone. A project's *Settings*, *Runs*, links there, and `arugula runs grant
show --project <name>` says whether a project has one. A grant lasts 90 days
unless the owner picks another length: renew it before it expires to keep
sessions starting.

**Sessions already going when you update** aren't ended. A turn under way
finishes. Until the project has a grant, the session takes no follow-ups,
anything queued for it is dropped, and its thread says so once. Once an owner
allows runs, replies go on as before.

**Revoking the grant** ends the project's agent sessions too: at once with
*also stop the runs and agent sessions going*, otherwise when a turn under way
finishes. Each cloud workspace checks the grant before a session starts and
before each turn, and an agent run needs the grant's permission to instruct as
well as to start.
- **Hide done rows in Steps** (#2344). The Done button sits beside Lanes and Steps, and only in Steps. Hidden, a phase
says how many done rows it holds ("3 done"), and the arrows to or from them go
with them.

## Fixed

- **Updating on Windows from PowerShell 7** (#2320). arugulad update on Windows no longer fails to unpack the release when the daemon or the shell that ran it came from PowerShell 7.
- **A machine's Docs page under the panes' header** (#2321). The Docs page drew a bar of its own over the window, so in the macOS app it
sat in the titlebar beside the traffic lights, with a different Commands
button. It now sits under the workspace's header, beside the rail, as the
panes do, and the rail lights Docs rather than Panes. A machine on its own,
with no Docs on its rail, keeps Panes lit.
- **An agent started on an issue reads it** (#2322). `start_agent` with `issue` keeps the issue's project on the agent's block, and
that is the agent's current project: its `forge_read` of `"#N"` and its
`issue_write`, `board_read` and `link` calls go there, after any `project` it
names and before the project its clone's repo is linked to. Its environment
has `ARUGULA_PROJECT`, so the `arugula issue` it runs looks there too.

A `#N` that isn't there now names the project searched, why that one, and that
`project` picks another.
- **A merged PR closes only what it says it closes** (#2323). Two ways a merge closed issues it only mentioned are gone:

- In a PR's description, only `Closes #N` (or `Fixes`, `Resolves`) and `Arugula #N` close an issue. Any other `#N`, such as `(#N)` in passing, links the issue to the PR without closing it. `(#N)` in the title still closes.
- A branch named `feat/N-…` no longer closes #N when the title or description says `part of Arugula #N`.

When a merge does close an issue, its timeline and its board row say which pull request closed it and by which words, such as `"Closes #N" in the body` or `the branch feat/N-…`, so a wrong close is easy to spot.
- **A Doc from the platform goes into a team once, with pictures** (#2346). A Doc written on the platform now goes into a team the way a Doc from a machine
does: Share with… records where the team's Doc came from, so sharing it twice
makes one team Doc and the second says "Already in" the team, with a link. Its
pictures come too. If you change your Doc afterwards, the team's Doc offers
Update, and the team's own edits never touch yours.
