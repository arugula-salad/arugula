# Arugula 0.57.0

Step 4 of the platform roadmap (#1204): control can keep a GitHub repo's PRs
and issues as platform rows, so a phone can see them and act on them while
every machine sleeps. Nothing changes until a repo is linked to a project.
Linking for hosted control comes with M173 (#1219), after the App's new
permissions are approved.

## Control

- **Link a repo to a project** (M163, #1259). A project member who
  maintains the repo on GitHub links it from the project's settings, from
  `arugula project link OWNER/REPO`, or from MCP's `link_repo`. If the App
  isn't installed there yet, you're sent to install it first. Unlinking,
  or an uninstall, purges the repo's rows within a day.
- **The mirror** (M164, #1261). The App's webhooks write a linked repo's
  PRs, issues, checks and reviews as metadata: never a body or a comment's
  text. One poller per repo backfills it and reconciles it every few
  minutes, fixes what a webhook missed (counted as drift), and keeps a
  share of GitHub's rate limit back for reads and sends.
- **Every read checks the viewer** (M165, #1260). A private repo's items are
  shown only to people GitHub says can see the repo, by their numeric
  GitHub id. Project membership alone never shows one. A removed
  collaborator is cut off at GitHub's next event, on both platform
  machines.
- **Bodies on read** (M166, #1280). Opening an item reads its body and
  comments from GitHub and keeps them a few minutes in memory. A project
  can opt a repo in to keeping them, which also makes them searchable.
  Opting out deletes them at once.
- **Down-scoped tokens and an audit log** (M167, #1258). Every App token is
  for one repo and the least it needs. A read can't get a write token.
  Write tokens are used once and revoked. Every mint is logged without its
  value.
- **Drafts are platform rows** (M170, #1262). An updated machine uploads
  its waiting drafts on linked repos once, and they show on the phone.
- **The inbox** (M171, #1282). The platform works out each member's inbox
  (review requested, checks failed, changes requested, assigned, a draft
  waiting) and pushes it. It's at `/inbox` on the platform page, and in
  `arugula forge inbox`.
- **Send as the person** (M168, #1283). Send on the platform page posts the
  draft on GitHub as you, with a one-use user token that's never stored.
  If that can't happen, the platform asks one of your online machines to
  send it with `gh`. Agents draft; only people send.

## Daemon, CLI and MCP

- **Typed forge operations** (M169, #1281). `POST /api/forge/ops`, MCP
  `forge_read` and `forge_draft`, and the CLI's `arugula pr view|list|checks`,
  `pr comment|review`, `issue create|comment` and `arugula draft …` all work
  on linked repos with no block open.
- **Linked blocks are pins** (M172, #1285). A PR or issue block on a linked
  repo reads the platform, and its machine makes no GitHub call for it.
  Unlinked repos, Forgejo and GitLab work as before.
- The GitHub reader is its own crate, `arugula-forge-github`, shared by the
  daemon and the platform (M160, #1234).
