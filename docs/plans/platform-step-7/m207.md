## New records

- **A run is a platform object on a hosted workspace.**
  - Triggered by a schedule, an event or a person.
  - The platform writes the run record, using S37's states.
  - The chant driver also writes chant's ledger for releases chant manages, and the platform links to that entry.
- **One standing grant per project starts runs.** An owner's device signs it once, it's revocable, and the platform never signs.
- **Run logs on hosted workspaces are readable by the platform,** kept 30 days. Personal machines are out.
- **A deploy needs an owner device's approval,** bound to the operation's bytes (environment, plan digest, source).
  - It goes stale if anything else applied to the environment after it was planned.
  - **Agents never approve,** whatever grant or identity they act under.
- **A driver is a run with a credential.**
  - Credentials are sealed per project, injected for one run, short-lived, never a kubeconfig.
  - A checked-in list names every environment whose secrets exist.
- **The deploy event log is append-only.** Approvals can be verified by anyone. It isn't WORM.
- **Driver order:** chant→Fly, then apps-platform. planter comes in step 8.
