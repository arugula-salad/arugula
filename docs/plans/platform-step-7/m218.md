M218: the deploy approval

Part of #TRACKER. Needs M217. Builds on S37's work approval (q3).

## What

- **The approval is S37's work approval,** over an operation whose bytes are the environment, the plan digest and the source.
- **Only a project owner's device can sign it.** The platform stores and shows it, but can't forge it.
- **Agents never approve:**
  - No grant, MCP tool or thread message counts as an approval.
  - An agent can plan a deploy and ask for an approval, and that's all.
  - Enforce it in code, with tests, including an agent on the owner's own machine (aru-091).
- **The phone gets approve and deny cards** showing the plan digest and the operation, approved with a passkey.

**Done when:**
- Jake approves a test deploy from his phone.
- A stale deploy and an agent's attempt are both refused, in tests.
