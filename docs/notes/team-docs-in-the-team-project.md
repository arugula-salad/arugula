In a team's context (a repo or issue of a team project, or a team machine) the `doc` tool's `new` makes the Doc in the team's project instead of on the machine, and `fill`, `asset` and the Doc block go there too. Nobody picks where: a personal machine, or one with no control, keeps its Docs as before. Give the machine the Write Docs power over the project (Settings, Access) first; without it the agent is told how, and nothing is kept on the machine instead. With control out of reach the block shows the last Doc it read, read-only. A public link for a team Doc isn't offered yet: `share` gives the team's page.
