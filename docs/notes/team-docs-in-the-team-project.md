In a team's context (a repo or issue of a team project, or a team machine) the `doc` tool's `new` makes the Doc in the team's project instead of on the machine, and `fill`, `asset` and the Doc block go there too. Nobody picks where: a personal machine, or one with no control, keeps its Docs as before. Give the machine the Write Docs power over the project (Settings, Access) first; without it the agent is told how, and nothing is kept on the machine instead. With control out of reach the block shows the last Doc it read, read-only. `share` makes the Doc's public link (Arugula #871) and answers it with the team's page: the platform keeps the link's key, this machine seals the Doc and puts the ciphertext to control, which never has the key; the Doc's page and the team's Docs list make, update and revoke it too.
